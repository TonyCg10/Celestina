# Evidence: the skeleton builds and opens the window with the empty state

- **Date:** 2026-10-09
- **Scope:** the Calcita skeleton, delivered inside suite unit `EXT-1-A` of
  [the suite plan](../../../docs/plans/archive/2026-10-09-reading-and-capture.md)
  and described in prose in
  [CAL-1's plan](../plans/active/2026-10-09-cal-1-foundation.md): the whole of
  `calcita/` and the app icon
- **Environment:** CachyOS, Rust 1.98.1, cxx-qt 0.9.1, Qt 6.12.0
- **Artifact:** the `calcita` release binary in the shared Cargo target, not
  installed

## Procedure

The full command list with exit codes is in
[the registration evidence](../../../docs/evidence/2026-10-09-calcita-registration.md).
The skeleton's own gates, all exit 0:

```sh
cargo build --release --locked            # in calcita/
sh calcita/scripts/qml-tests.sh
sh calcita/scripts/smoke.sh --binary <release binary>
bash scripts/qmllint-cxxqt.sh calcita
```

Single instance, by hand under a private session bus (`dbus-run-session`),
offscreen: with one Calcita running, a second launch with a path exited at
once with status 0 after handing its request to the first.

## Result

- **Exit:** 0 for every command.
- **Observed:** `tst_main.qml` builds the real `Main.qml` over QML stand-ins
  for the two Rust types (`tests/qml/stubs`): the window constructs, starts
  its activation adapter once, shows the card «Sin documento» with «Abrir…»,
  and the button emits `openRequested` (5 passed, 0 failed). The smoke starts
  the binary offscreen for 8 s with no QML error and reads
  `calcita-smoke: empty=true textScale=1 fontBody=13`. The Rust tests (2)
  cover the activation adapter and the appearance values.
- qmllint reports one warning, in the shared
  `celestina-style/CelestinaIcons.qml` (see the registration evidence);
  Calcita's own QML lints clean.

## Limits

- No document opens yet; «Abrir…» does nothing. Nothing is installed. The
  real compositor's raise, the keyboard and the look on the session are for
  the author.
