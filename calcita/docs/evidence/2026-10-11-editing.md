## Decisions

- **The domain stays in `calcita-core`.** `annot::edit` owns what may
  change (only FreeText, Highlight and Ink, of any author; a text box's
  text and colour only when it carries no `/RC`; text only in WinAnsi; a
  text box always as tall as its lines, its top-left corner kept as the
  page is shown), undo and redo (the edit set: edits in effect and edits
  undone, a new edit forgetting the undone), the shown model
  (`EditSet::apply`) and what the writer must do (`EditSet::resolve`: add,
  rewrite as it ends, remove). The constructors from the displayed page
  (`text_box`, `highlight`, `ink`) are where geometry crosses
  `annot::coords`; QML and the adapter speak only displayed points.
- **Writing** (`annot::write`) loads with the reader's bounded loader (the
  same size, inflation and encryption rules) and appends one
  `IncrementalDocument` update built from the same bytes: page `/Annots`
  (an indirect array copied into the update, else the page with its
  inline array), each added or rewritten annotation, its appearance
  stream and one Helvetica font object per update. A text box only
  moved or resized keeps the appearance its program drew (viewers map it
  onto the new rectangle), its `/DA`, `/Contents` and `/RC`; one whose
  text, size or colour changed is laid out again (`edit::lays_out_again`,
  the one rule the edit set and the writer share), as is every changed
  highlight and drawing. A deleted
  annotation leaves `/Annots` with the pop-up it names; the objects stay
  in the file, unreferenced, as an incremental update must. Text strings
  are ASCII literals or UTF-16BE with the mark. New annotations get `/NM`
  `calcita-<time>-<pid>-<n>` and `/F 4` (print).
- **Appearances** (`annot::appearance`): the `/BBox` is the `/Rect` in page
  space with the identity matrix, so nothing is transformed twice. Text is
  Helvetica in WinAnsi (nothing embedded), broken with Adobe's Helvetica
  widths (the standard-14 metrics), 2 points of padding and 1.2 font sizes
  per line, clipped to the box and drawn upright as the page is shown (the
  matrix comes from `coords`, so a turned page reads correctly). A
  highlight fills each quad under `/BM /Multiply`; a drawing strokes with
  round caps and joins.
- **The edit-mode render** is an in-memory copy (`write::hidden_copy`, the
  editable annotations with `/F` Hidden) that the beginning worker
  registers with the provider under a fresh revision
  (`calcita_page_provider_show_copy`, a mutex-guarded registry of
  implicitly shared bytes); the render thread opens it through a `QBuffer`
  (a random-access device loads at once, checked offscreen), kept among its
  open documents like a file. The window's pages switch to that revision
  only once the copy is registered; leaving drops it, and so does the
  editor's destructor.
- **The revision in the page address** (`image://calcitapage/<page>/
  <revision>/<key>`, from one process-wide counter in `pages.rs`) closes
  CAL-2-A's follow-up: a window takes a new revision when it opens a
  document, when a check finds the file changed on disk (the window asks
  when it is activated; the model reader compares the file's size and
  modification time with its last read, publishes nothing when equal, and
  reads the model again when not), after a save that replaced the file,
  and for the edit copy. The window then loads its `PdfDocument` again at
  the page it was read at. A window that is editing keeps the version it
  began on, and the save refuses a file that changed since then.
- **Saving** (`src/saving.rs`) composes the suite's owners: «Guardar
  ambas» lands through `atomic_file::land_media` under
  `siderita_ops::next_available`'s «(editado)» name, which never replaces
  a file; «Guardar solo la editada» lands the result under a hidden name
  first, then sends the original to the Trash (`siderita_ops::trash`,
  behind a `Bin` seam the tests fake), then publishes without replacing.
  Fluorita's engine lands an edited picture in the same order
  (`fluorita_engine::land_file`); it is not reused because it lives in
  Fluorita's media engine with Fluorita's types, and both rest on the same
  two owners. `siderita-ops` is a path dependency of the application,
  justified in its manifest (a pure crate whose one dependency,
  `celestina-core`, was already there); it adds no crate to the lock beyond
  itself.
- **After a save** the session ends. A copy beside becomes the window's
  document (the controller's `renameDocument`; the reading place and mode
  are remembered for it first, so recents, the page and the reading mode
  survive); a replaced original is loaded again at a new revision.
- **The editor QObject** (`CalcitaEditor`, one per window) begins on a
  worker, publishes the editable annotations as one JSON array in
  displayed points (so QML rebuilds from one consistent value), checks
  every edit through the edit set (a refusal is a Spanish notice), and
  saves on a worker; results are generation-tagged. QtPdf's selection
  outlines reach it as polygons (`QList<QVariant>`), each turned into its
  box in Rust. A text box's position arrives as a `QPointF`, which keeps
  the invokable within clippy's argument limit without an `allow`.
- **QML**: the bottom toolbar follows Fluorita's editor (toggle tools,
  swatches, a capsule for undo and redo, the two outcomes by name) with
  the four tools as text buttons, the six colours as the theme's accent
  keys, and the size as three dots named for the armed tool. A highlight
  takes the accent itself; text and drawings take the theme's emblem ink
  of the accent (`iconEmblemInk`), the deep ink of the same hue made for
  the same paper sheet the pages lie on. Each built page loads the
  window's `AnnotationLayer` (highlights, drawings, text boxes, the box
  being written and the stroke being drawn) through `PageView.pageLayer`;
  the text is drawn in Helvetica (fontconfig's metric-compatible face) in
  the page's points, scaled with the page. While editing, links do
  nothing and the page's own text selection serves only «Resaltar»; the
  reading mode waits. Enter on a selected text box edits it, beside the
  double click, so the keyboard reaches every tool. The window's edit keys
  stand aside while a text field has the keyboard.
- **Recents**: the controller now publishes the recents' names before
  their keys, so a row built for a new key reads its name at once (the
  move to a saved copy added a row and showed the race as a QML warning).
- **AGENTS** loses "Calcita reads documents; it never writes to them":
  it writes only when the person saves, beside or replacing through the
  Trash, never in place.

## Limits

- Offscreen only. Drawing with a real pointer or stylus, the double click
  (qmltestrunner spaces its synthetic clicks past the double-click
  interval, so the tests drive Enter instead), typing with a real input
  method, the look of the toolbar and of the items at real scales, the
  Trash on the session's own volume, and the saved files in other viewers
  are VAL-CAL-EDIT.
- The text box shown while editing is laid out by Qt with fontconfig's
  Helvetica substitute; the saved appearance by Calcita with Adobe's
  widths. Both use the same metrics, but the line height while typing is
  the font's own (TextEdit has no fixed line height), so a long text may
  wrap a word differently until it is committed.
- Another program's FreeText with a callout line (`/CL`) or rectangle
  differences (`/RD`) is moved by its `/Rect` only; a rich-text one keeps
  its text and colour (it moves and is deleted).
- The edit-mode copy is made by reading the file twice (once for the
  model, once for the copy); a file past the reader's bound refuses edit
  mode with the reader's notice.
- Not run: `complete-production.sh` (the landing runs it), and Okular or a
  browser on the saved files (VAL-CAL-EDIT).
