## Decisions

- **One owner for the form.** The field walk (names, inheritance, kids
  with and without `/T`) moved from `annot::read` into `annot::form`,
  which now reads every widget of a field (page, rectangle, `/MK`
  background and border, border width, on-state) and what Calcita may do
  with it (`Fill::Text(TextFormat)`, `Fill::Checkbox { on }`,
  `Fill::No(ReadOnly)`); `read_fields` delegates and keeps its answer
  (each field at its first widget), so CAL-2-A's tests pass unchanged.
- **Showing.** QtPdf draws no widget, so the reader's one load
  (`form::view`: annotations, page boxes, fields and the copy) stamps each
  shown widget (not hidden, not `NoView`) into an in-memory incremental
  update: the page's own content wrapped in `q`…`Q`, then each normal
  appearance (`/AP /N`, or its `/AS` state) drawn as a form XObject under a
  name the page's resources do not use, with the matrix ISO 32000-1,
  12.5.5 gives (the `/BBox` through its `/Matrix` onto the `/Rect`); the
  page's resources, even inherited ones, are written into the page. A
  document whose table was rebuilt by scanning is shown without the copy
  (no `/Prev` to point at). The copy is never written to disk.
- **The copy in the window.** The reader registers the copy with the page
  provider under a revision of its own (`pages::next_revision`, from the
  worker) and the window moves its pages to that revision when the read is
  published, so the image cache never mixes the file and the copy; the
  copy is dropped when the window moves to another revision, when a read
  arrives for a document no longer shown, when the window cannot take the
  read any more, and when the window goes. Until the read lands, the pages
  show the file (without the widgets).
- **Editing.** The edit-mode copy (`write::hidden_copy`) hides the editable
  annotations and stamps the widgets Calcita does not fill (radio buttons,
  lists, signatures, read-only fields); the ones it fills are QML controls
  over their widgets while editing, as the editable annotations are, so
  nothing is drawn twice. The editor publishes its model before `editing`
  turns, so the window moves to the editor's fields in one step.
- **Filling.** `Edit::Fill(FieldId, FieldValue)` joins CAL-2-B's edit
  set: checked when pushed (`form::check_fill`), applied by
  `EditSet::fields`, resolved to the fields whose value changed
  (`Resolved::filled`), undone and redone with the annotations, and written
  in the same incremental update: `/V` on the field (inherited values
  included), and on each widget a new `/AP` for a text field or `/AS` for
  a checkbox. The text appearance's `/BBox` is the widget's rectangle in
  page space; it draws the `/MK` background and border (`/BS /W`, else
  `/Border`, else 1), then the text as variable text (`/Tx BMC`) clipped
  inside the border with 2 points of padding, in Helvetica in WinAnsi at
  the `/DA` size and colour; size 0 is fitted (at most 12 points, to the
  height and then the width, never under 4; a multiline field shrinks by
  half points until its lines fit), `/Q` aligns each line, a comb centres
  one character in each of `/MaxLen` cells, a multiline field breaks lines
  with the text box's own breaking. A checkbox's on-state is the name its
  widgets' `/AP /N` give besides `Off`; a checkbox whose widgets name none,
  or different ones, is not filled. `NeedAppearances` is left as it is.
- **Refusals.** Radio buttons, choice lists, push buttons, signatures,
  fields marked read-only, password and file fields are shown and never
  written; tapped, each says why (`form::ReadOnly::message_es`, through
  the published model). `AnnotError` gains `ReadOnlyField` and `TooLong`.
  Encrypted and damaged documents refuse filling as they refuse editing.
- **Text strings.** `write::text_string` writes a string with a control
  character (a line feed) as UTF-16 with its mark, since `lopdf` reads a
  literal line feed through PDFDocEncoding, which leaves it undefined: a
  multiline value, and a text box of two lines since CAL-2-B, read back
  without their line breaks. The regression test covers the text box; it
  failed against the earlier writer (`text.is_ascii()` for a literal).
- **QML.** `FormLayer.qml`, loaded by each built page through
  `PageView.formLayer` over the annotation layer, counts the page's
  widgets in its repeater, so a new value updates each control in place
  and the field being typed in keeps the keyboard; values are committed
  at once (the keyboard leaving, Enter on one line, Tab, Escape), so
  leaving or closing right after typing finds them. Tab and Shift+Tab ask
  the window, which picks the next field Calcita fills in the form's
  order, brings it into view with `PageView.reveal` (scrolling as little
  as it takes) and asks for it (`formFocusOrder`, `formFocusPending`,
  `formFocusSerial`), so a control on a page built only then takes the
  keyboard. The checkbox claims Space from the window's next-page
  shortcut; the text controls join the window's `editTyping`, so the edit
  keys are theirs. While highlighting or drawing, the fields stand aside.
  Text is drawn in Helvetica at the size the core lays it out at, in the
  field's colour; the controls are tinted `accentSoft` and framed with the
  focus ring when they have the keyboard; a checkbox's mark is black, as
  the forms' own check.
- **Smoke.** `CALCITA_SMOKE_FILL` (the controller's `smokeFill`) fills the
  fixture's «name» and «agree» and saves beside; the report adds the
  fields Calcita fills and their values.
- **Commit subject.** The plan's `Fill text fields and checkboxes in
  forms` is refused by the commit guard («fill» is not among its
  imperatives), so the unit's subject is `Add filling of text fields and
  checkboxes in forms`.

## Review round 1

- **Widgets not shown** (`annot/form.rs`, `Widget::shown` and
  `NOT_SHOWN`; `src/editor.rs`, `json_fields`): a widget's `/F` is read; a
  hidden or `NoView` widget is neither stamped nor published, so it takes
  no tap, no control and no place in Tab's order (one rule for both; see
  round 2 for the invisible flag). Tests: `annot_form`'s
  `hidden_and_no_view_widgets_are_not_shown_but_invisible_ones_are`; the
  editor's
  `a_hidden_field_over_a_visible_one_takes_no_tap_and_no_place` (a hidden
  field first in the form, over «name»: «name» is the first in the order).
- **A refused value** (`qml/edit/FormLayer.qml`, `commit` and `revert`):
  the layer fills through the editor (`required property CalcitaEditor
  editor`, as the annotation layer does) and, when the editor refuses
  (its notice says why), the control shows the field's own value again;
  nothing joins the edit set, so a save writes the value the field had.
  The stand-in refuses text outside Latin-1 as the Rust object refuses
  text outside WinAnsi. Tests: `tst_form`'s
  `test_a_refused_value_gives_way_to_the_fields_own` (the notice, the old
  value, `edited` false, Tab still moving on), and Enter keeping an
  accepted value in its field.
- **Line breaks from other programs** (`annot/read.rs`, `decode_text`):
  PDFDocEncoding's tab, line feed and carriage return are decoded as
  themselves (ISO 32000-2, Annex D), which `lopdf`'s table leaves
  undefined, in the one decoder every text string goes through; and a line
  break reads as a line feed whatever ends it (CR LF, CR or LF): the stated
  choice, so a multiline value or a text box from any program reads, shows
  and saves back with its lines. Tests:
  `a_line_break_another_program_wrote_reads_and_saves_back` (`/V
  (line1\rline2\tend)` reads `line1`, a line feed, `line2`, a tab, `end`;
  filled again and saved, it reads back with its line break; CR LF in a
  single-line field reads as one line feed) and
  `a_text_box_another_program_broke_with_a_cr_reads_with_its_line`.
- **A stamped copy on its way** (`src/document.rs`, `in_flight`,
  `take_copies`): the reader records each copy it registers until its read
  reaches the window; a window destroyed after the read was queued drops
  them in `Drop`, as CAL-2-B's editor does with its copy. Test:
  `a_window_going_away_drops_its_copies_shown_and_on_their_way`.
- **Field nodes and ids** (`annot/form.rs`, `FieldWalk::visit`, `FieldId`;
  `annot/edit.rs`, `Edit::Fill`): a kid without `/T` but with kids of its
  own is a field node, not a widget; a field is found by its object
  (`FieldId`, else its place in the walk), its joined name kept for
  showing, so fields that share a name, or have none, never collide.
  The plan's `Edit::Fill(FieldName, FieldValue)` is therefore
  `Edit::Fill(FieldId, FieldValue)`; the published widgets carry the id
  (`field`, `o8.0`), which `fillText` and `setChecked` take. Tests:
  `fields_are_found_by_id_whatever_their_names` (two fields named «dup»
  and one unnamed, each filled with its own value) and
  `a_kid_without_a_name_but_with_kids_is_a_field_node`.
- **Escape on a checkbox** gives the keyboard back to the pages, as in a
  text field. Test: `test_escape_on_a_checkbox_gives_the_keyboard_back_to_the_pages`.
- **Each widget's own `/DA` and `/Q`** (`TextFormat::of`): a kid widget's
  own default appearance and alignment override its field's in the
  saved appearance, the control's size and colour and its alignment.
  Test: `each_widget_lays_its_text_out_with_its_own_da_and_q` («copy» at
  10 pt black on page 1, 14 pt red right-aligned on page 2).
- **A turned appearance** (cheap, added): an appearance whose `/Matrix`
  turns it a quarter is carried onto its widget by the bounds of its
  turned box. Test: `a_turned_appearance_is_carried_by_its_matrix_onto_the_widget`.
- The full check list ran again, every command exit 0; the smoke's
  measures are unchanged.

## Review round 2

- **The invisible flag** (`annot/form.rs`, `NOT_SHOWN`): only hidden and
  `NoView` keep a widget off the page; invisible (bit 1) applies to
  annotation types a viewer does not know (ISO 32000-1, table 165), so a
  widget marked so is stamped and gets its control, as QtPdf and poppler
  show other annotations marked so. The test now marks «city» invisible
  and finds it shown and stamped (seven of page 1's nine widgets stamped).
- **A line break in a single-line field** (`annot/form.rs`, `folded`;
  `annot/edit.rs`, `EditSet::push` and `accepts`): a fill that changes a
  single-line text field takes its value with each line break (CR LF, CR
  or LF) and tab as a space, so a value another program wrote with one is
  editable there; a fill giving the field the value the file has is kept
  as it is and never refused, so it rewrites nothing (and an untouched
  control commits nothing: `tst_form`'s
  `test_a_value_with_a_line_break_is_not_rewritten_untouched`). Test:
  `a_line_break_in_a_single_line_field_becomes_a_space_once_edited`
  («one», a line feed, «two» untouched resolves to nothing; edited with
  «!», a tab and «ok» it saves and reads back as «one two! ok»).
- **The refusal of a fill** speaks of a field: `AnnotError::NotFillable`,
  whose Spanish notice names a field, for a value of the other kind,
  a line break `check_fill` meets in a single-line field, or a field that
  is not there, in the core and in the editor, instead of the annotation
  notice.

## Limits

- Offscreen only. Filling a real form with the pointer and the keyboard,
  the controls' look at real scales, typing with an input method, and the
  saved file in a browser or Okular are VAL-CAL-FORM.
- `/MK /R` (a widget's own rotation) is not honoured: the regenerated text
  is drawn in the page's user space, so on a page shown turned the saved
  text turns with it while the control shows it upright.
  Deferred by the review, recorded in STATUS's known issues.
- A text field's new appearance draws only its `/MK` background and border
  around the text: any other drawing of the old appearance (a comb's
  dividers, a custom frame) is not kept.
- Hybrid XFA forms keep their `/XFA` data, which Acrobat may prefer to the
  values written; a field's `/RV` (rich value), its actions and scripts
  (format, validate, calculate) are not touched or run.
- The controls are laid out by Qt with fontconfig's Helvetica and the
  appearance by Calcita with Adobe's widths; a long value may wrap a word
  differently in a multiline control.
- Each window holding a form keeps a stamped copy of its file in the page
  provider (and, while editing, the edit copy too), as large as the file.
- `complete-production.sh` was not run (the landing runs it).
