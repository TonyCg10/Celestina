## What was corrected

| Finding | Symbol | Correction |
|---|---|---|
| `GRA-C1` | `grafita-core/src/document.rs::adopt_target`, new `Document::mark_saved_at`, `session.rs::receive_created` | Adopting the written file and pinning the savepoint became two operations. `receive_created` now compares the revision `Completion::Created` already carried with the document's, takes the existing `SaveApplication::StillDirty` path when they differ, and does not close on that path |
| `GRA-A1` | `grafita/src/session.rs::save_url`, `qml/components/DocumentView.qml` | The chooser's URL goes to the same `url::local_path` the open path uses. The QML `substring(7)` is gone; the surface hands the URL over whole |
| `GRA-A2` | `session.rs::save`, `session.rs::save_and_close`, `qml/Main.qml` | A clean document queues nothing, a state already with the worker queues nothing, and the `Ctrl+S` shortcut is guarded exactly as the footer button is |
| `GRA-A3` | new `DocumentSession::cancel_save_as`, `GrafitaSession::cancel_save_as`, `DocumentView.onRejected` + `saveCancelled` signal, `Main.qml` | A dismissed chooser disarms `close_after_save`, the adapter's quit flag and the window's `quitCursor` |
| `GRA-A4` | `session.rs::receive` | `pending_classify` membership is tested before the staleness filter, so an open asked for after a classify no longer drops the classify's answer |
| `GRA-M2` | `save.rs::create`, new `save::CreatedFile` | An existing destination is canonicalised whole, so a symlink is written through instead of replaced; the directory is synced after the rename and the real `Durability` is carried in `Completion::Created` rather than asserted by the session |
| `GRA-M4` | `history.rs::trim` | Eviction drops a group whole or not at all, and never drops the only action on the stack, so an undo after a replace-all larger than the 512-change bound cannot land in an intermediate state |
| (audit-adjacent) | `session.rs::receive_open` | The live search is reset when a new document is adopted, as `new_document` already did |
| (audit-adjacent) | `search.rs::LiveSearch::step` | With nothing selected, forwards selects the first match and backwards the last, instead of skipping the first |
| (audit-adjacent) | `grafita/src/session.rs::publish` | A refusal message naming the file now outranks the generic wording of the same refusal, which used to overwrite it before it was ever shown |

## Procedure

```sh
cargo test -p grafita-core            # in celestina-rs/
cargo clippy -p grafita-core --all-targets
cargo fmt -p grafita-core -- --check
cargo check && cargo test && cargo clippy   # in grafita/
cargo fmt -- --check                        # in grafita/
scripts/qmllint-cxxqt.sh grafita
bash scripts/check-architecture-contract.sh
python3 scripts/check-language-contract.py
```

Each corrected behaviour was additionally checked by reverting the correction
alone and confirming that the new test fails against the previous code.

## Result

- `cargo test -p grafita-core`: 83 + 23 + 27 passing, 0 failing. The session
  suite grew from 18 to 27 cases.
- `cargo clippy -p grafita-core --all-targets`: no warnings.
- `cargo fmt` clean for the crate and for the application.
- `grafita`: `cargo check` and `cargo clippy` clean of Rust diagnostics
  (the C++ warnings printed by the CXX-Qt build come from system Qt headers);
  `cargo test` 7 passing.
- `scripts/qmllint-cxxqt.sh grafita`:
  `OK — org.celestina.grafita (62 avisos no fatales del baseline)`. It linted
  against the module generated by the previous release build; no release build
  was run in this unit.
- `bash scripts/check-architecture-contract.sh`: colour, contrast and QML
  visual contracts OK. It reports three line-growth errors, all in unrelated
  in-flight worktree changes this unit did not touch —
  `celestina-rs/crates/magnetitad/src/main.rs`, `siderita/src/controller.rs`
  and `siderita/qml/views/FolderView.qml`.
- `python3 scripts/check-language-contract.py`: no Grafita or `grafita-core`
  row. Its four errors belong to `magnetita-core`, `siderita-qt`, `fluorita`
  and `siderita`, again unrelated in-flight work.

### Regression checks

Each of these failed with the correction reverted and passes with it in place:

```text
editing_during_a_save_as_leaves_the_document_dirty
a_save_as_that_left_work_behind_does_not_close_the_document
saving_twice_over_the_same_state_writes_once_and_raises_no_conflict
a_classify_answer_survives_an_open_asked_for_after_it
opening_another_document_clears_the_live_search
a_replace_all_larger_than_the_undo_bound_is_reversed_completely
a_save_as_onto_a_symlink_writes_through_it
history::tests::the_bound_never_discards_part_of_one_action
```

`cancelling_the_destination_chooser_disarms_the_pending_close`,
`find_next_after_a_replace_all_selects_the_first_occurrence` and
`stepping_with_nothing_selected_lands_on_an_end_of_the_list` cover the
remaining corrections; the first exercises a method that did not exist before.

## Limits

- **No production flow.** `build-production.sh`, `verify-production.sh`,
  `deploy-production.sh` and `complete-production.sh` were not run, no version
  was bumped and `docs/version-history.tsv` was not touched: the author
  excluded them from this request. The unit therefore stays `active` and
  carries no inventory.
- **`GRA-M6` (per-keystroke O(n) work against the declared 64 MiB ceiling)** is
  an incremental-reconciliation redesign, not a patch, and belongs to its own
  unit with its own measurement.
- **`GRA-M7` (U+2028 round-trip through `QTextDocument`)** is marked
  speculative by the audit that raised it and cannot be settled without running
  the application against a real widget. It stays open.
- The dialog's real behaviour against the session's file-chooser portal — that
  a destination with `#` or `%` in it now produces the name the user typed, and
  that dismissing the chooser leaves no tab closing by itself — needs a real
  session and is recorded as `VAL-GRA-SAVEAS`.
