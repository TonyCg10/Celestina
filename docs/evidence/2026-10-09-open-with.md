# Evidence: open-with inside the suite

- **Date:** 2026-10-09
- **Scope:** CONV-1-D — suite
- **Environment:** CachyOS, rustc 1.98.1, Qt 6.12.0, Python 3.14.7; debug and release builds
  in the shared session Cargo target
- **Artifact:** not applicable

## Change

- Siderita: an entry's context menu (`qml/menus/EntryContextMenu.qml`) gains
  a `GlassMenuSection` «Abrir en» between «Abrir» and «Abrir con…», filled
  by an `Instantiator` that inserts its entries right after the header. The
  menu hands a new narrow QObject, `SideritaSuite` (`src/suite.rs`, created
  in `FolderActions.qml`), each acting entry's key and whether the folder
  model says it is a folder (`entryTargetsDirectory`); media is decided by
  name (`fluorita_core::MediaKind::classify_path`), so nothing reads the disk
  on the Qt thread. The decision is `apps::suite_targets(&[ItemKind]) ->
  Vec<Target>`: Grafita for any file, Fluorita for media or one folder,
  Hematita for one folder, the phone for any file or files; a selection
  mixing folders and files gets nothing. `apps::probe_installed` looks up
  each application's desktop entry (`desktop_entry::find` over
  `application_search_dirs`, the scan's shadowing rule) once on a worker at
  start, and an application without one is not offered. The menu expands
  `phone` into one entry per phone whose `phoneInfo` says connected:
  `"Enviar al móvil"` for one, `"Enviar a %1"` with the name for each of several, none
  when Magnetita's daemon is absent or nothing is connected.
- Opening goes through `apps::open_in` (the CONV-1-A decision table:
  delivered over `org.celestina.Application1.Open`, else spawned with every
  path — `controller::shell::spawn_detached_all`, Hematita through
  `gtk-launch` by its desktop id); a failed start reaches `opError`
  through the object's `failed` signal. Sending queues one `SendFileUri`
  per file on the device model's worker (`devicemodel::send_file`), the
  byte-exact variant of `Devices1.SendFile` (ADR 0008).
- The old single-file send item and the controller's
  `send_to_phone` invokable are gone; `siderita/src/controller.rs` falls
  from 746 to 744 lines and its architecture row is lowered. The
  language rows of `EntryContextMenu.qml` (13 → 12) and
  `controller/mounts.rs` (removed) fall with them.
- Magnetita: `org.celestina.Magnetita.desktop` keeps `Exec=magnetita` (no
  field code) and gains `MimeType=application/octet-stream;` and
  `[Desktop Action send]` (`Exec=magnetita --send %F`, `Name=Send to
  phone` and its Spanish `Name[es]`). `src/send.rs` parses the arguments
  (`--send PATH…` and `--dry-run`; relative paths taken from the working
  directory, names kept as `OsString` bytes). Only the explicit send action
  sends: a positional argument on the main entry is ignored with a stderr
  note and the window opens as before. A folder or a missing name after
  `--send` is refused before the bus. The plan comes from `ListDevices`: one
  connected device takes every file at once (`SendFileUri` each, on `main`
  before Qt starts) and the process exits; several open the window as a
  chooser alone (`SendChooser.qml`, the files already chosen), where the
  pick sends on the model's owned worker (`DevicesModel.chooseSendDevice`,
  answered by `sendFinished`) while the window shows «Enviando…»; success
  closes it, a failure stays on screen with the reason and sets exit 1;
  cancelling exits 0; none connected exits 1. While «Enviando…» is up the
  window refuses to close; the failure is recorded on the worker itself
  (`send::run_chosen`), and `main` waits for a send in flight (at most
  120 s, then counted failed) before the exit code.
  `--mirror` is now read with `args_os`, so a non-UTF-8 file argument no
  longer panics the launch. `celestina-core` becomes a direct dependency for
  `file_uri::from_path`; it was already in the closure.
- `celestina-settings`: `load_stored()` answers the file's values without
  the `CELESTINA_REDUCED_MOTION` override; `load()` is `load_stored()` plus
  the override, and the watcher's re-read is the same composition. A caller
  that reads, changes and saves starts from `load_stored()`, so a text-size
  change while the variable is set no longer writes `reduced_motion = true`.
  Cuprita's save path (being landed as CUP-1-I) switches to `load_stored()`
  in CONV-1-F; this unit does not touch `cuprita/`.

- GIO and the `MimeType`: with the entry alone in a scratch data directory,
  `gio mime application/octet-stream` lists it, but `gio mime image/png`
  does not: GIO lists only types an entry declares (and does not expand
  `image/*`), so the inherited `application/octet-stream` does not put
  Magnetita in a PNG's "open with". The entry keeps
  `application/octet-stream;` alone, as ruled; Siderita's «Abrir en» is the
  primary path. With no other handler in the scratch directory, GIO made
  Magnetita the octet-stream default; on the author's system another
  default may or may not exist.
- Siderita's README says the installed-application lookup runs once at
  start and the entries appear once it answers. `suite.rs` gains
  `item_kinds` with tests: a symlink to a folder is a folder, a broken
  symlink a file, media by name.
- `celestina-settings` tests: every test that sets
  `CELESTINA_REDUCED_MOTION` or `XDG_CONFIG_HOME` holds the file's
  `ENVIRONMENT` lock through `Home` for its whole body, and `Home::drop`
  clears the variable before the lock is released (`tests/watch.rs` is a
  separate process with its own lock); three consecutive runs passed.

## Result

- **Exit:** every command above exits 0.
- **Tests added:** Siderita `apps.rs` 7 unit (a text file, an image, one
  folder and two folders, mixed selections, the installed filter, a desktop
  entry marking an application installed, the QML key mapping);
  `tests/qml/tst_entry_menu_suite.qml` 7 cases over a stub controller and
  suite (each acting entry and its folder flag reach the suite, one send
  entry for one connected phone, one per connected phone and the device id
  sent, none offline, the entries follow the header, an application entry
  opens through the suite, the section hides when nothing applies);
  Magnetita `send.rs` 10 unit (no flag, paths after the flag, a file on the
  main entry ignored and never a request, a folder or a missing name
  refused, `--dry-run`, the flag alone, a non-UTF-8 name byte for byte, one
  device, several and none, the pick names a listed device only); Siderita
  `suite.rs` 2 unit (symlinks, media by name); `celestina-settings` 3 integration
  (the stored values ignore the environment, a read-modify-save under the
  override keeps `reduced_motion = false`, a missing file stores the
  defaults).
- **Observed:** qmllint rows unchanged (siderita 222, magnetita 38): the
  first versions added `unqualified` warnings from delegate `modelData` and
  an id that shadowed a member, fixed with `pragma ComponentBehavior: Bound`,
  delegate ids and a rename. Siderita QML tests 212 passed; Siderita unit
  194 passed; Magnetita unit 34 passed (1 ignored). A first fix version
  read `error.length` on a `QString` signal argument (one more qmllint
  warning); it compares with `""` now.

## Limits

- Magnetita's tests live in `src/send.rs`: a test under `magnetita/tests/`
  links the binary's generated Qt archive without its Rust half and fails
  to link, and the package has no library target.
- The sidebar menus (`SidebarContextMenus.qml`) are not given the section:
  places, bookmarks and devices are folders the entry menu already covers
  once opened; the spec offers either menu, and only the entry menu has a
  selection to decide on.
- A running instance that refuses the paths is reported on stderr only, as
  for the other `open_in` callers.
- Choosing Magnetita in another application's "open with" opens its window
  and ignores the file; sending is the `send` action's (and Siderita's).
- The chooser's look, the menu in a real session and a real send are the
  author's to judge.
