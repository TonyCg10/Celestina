## Hypothesis

A session can read about 40 KB instead of 373 KB before acting, and build
against a cache that stays under 40 GiB, without any landing verifying less
than it does today.

## Tangible outcome

A session build cache that a cap bounds and that a landed unit's worktree no
longer leaves behind; a lighter dev profile for session builds; an agent
preflight in tiers whose first tier has a budget that cannot grow back
unnoticed; and a light lane with a review cap and one list of sensitive paths.

## Scope

- U01 of the spec: the session dev profile, the cap on the session Cargo
  target (`SESSION_TARGET_CAP_GIB = 40`) and the closing of a landed unit's
  session worktree (`DEV-1-A`).
- U02 of the spec: tiers in the agent preflight and a budget for its first
  tier (`DEV-1-B`).
- U04 of the spec: the light lane, the review cap and the sensitive-path list
  (`DEV-1-C`).

## Exclusions

- U03 of the spec, the smoke in phases, belongs to the shell. A suite plan
  carries only `suite:` rows, so that unit gets its row in a `celestina` plan
  when its own plan is written.
- Production artifacts, their verification, version bumps, inventories,
  commit scope and hook integrity rules.
- Deleting or rewriting historical plans, specs, evidence or inventories.
- Trimming the applications' `STATUS.md` files.
- The author's global agent instructions, which live outside the repository
  and change only with the author's approval of the exact text.

## Build order

1. `DEV-1-A`: the dev profile, the cap and the auto-close, because every later
   unit builds in a session and pays back from the first landing.
2. `DEV-1-B`: the tiers and the budget, once builds are lighter.
3. `DEV-1-C`: the light lane and the review cap, which need no script change
   and rest on the tiers for the cheaper preflight.

## Implementation exit

Every row is `done`, the `now` budget test is green, and the session target is
under the cap after a landing.
