**Decision: `wpctl`.** The client (`cuprita_core::wpctl`, feature `wpctl`)
parses `wpctl status`, reads names with `wpctl inspect` and stream volumes
with `wpctl get-volume`, commands through `wpctl set-default`,
`set-volume`, `set-mute` and `set-profile`, and reads a card's profiles with
`pw-cli enum-params <device> EnumProfile` and `Profile` (`wpctl` changes a
profile by index but does not list them). The watcher re-reads
`wpctl status` on `pw-mon` events; it polls every 2 s only while `pw-mon` is
missing or ended, or PipeWire does not answer (aligned by CUP-1-G, see the
[final review](2026-10-08-final-review.md); as landed in CUP-1-E it also
polled every 2 s while `pw-mon` ran).
No new crate dependency; `pipewire` is not added. The scratch crate was
deleted after the spike.

## Design notes

- **Fixtures:** `tests/fixtures/wpctl-status.txt`,
  `pw-cli-enum-profile.txt` and `pw-cli-profile.txt` are this machine's
  output, with the session's Spanish descriptions replaced by PipeWire's
  English ones ("Analog Stereo", "Mono Input", …) so they satisfy the
  language contract (a `.txt` fixture cannot carry its exemption marker).
  The status fixture has two sinks (one default, muted), two sources and two
  streams.
- **Profiles:** `wpctl` sets a profile by index (`wpctl set-profile <card>
  <index>`) but lists none, so `pw-cli enum-params <card> EnumProfile` and
  `Profile` are read and `set_profile` maps the profile name to its index.
  `off` is never offered. No `pw-cli set-param` is needed.
- **Watcher:** `wpctl status` is parsed and compared parsed (its raw text
  names the `wpctl` client itself) on each burst of `pw-mon` events, and
  every 2 s only without `pw-mon` or PipeWire (since CUP-1-G). `pw-mon` wakes it, but
  only for nodes, devices and metadata (`MonitorFilter`): the client's own
  `wpctl` and `pw-cli` calls add and remove clients, ports and links, and
  counting those made the watcher wake itself forever in the first try.
- **Worker:** the audio worker is now driven by the watcher like the other
  two; the 5 s poll and `Worker::spawn` are gone.
- **Streams' endpoints:** a stream's port names its node by nickname
  (`USB2.0 Device:playback_FL`); the endpoint is the sink (or, recording,
  the source; a monitor port means the sink) whose description starts with
  that name, the longest match winning.

## Limits

- Each snapshot spawns one `wpctl status`, one `inspect` per endpoint and
  stream, one `get-volume` per stream and two `pw-cli` per card (here 4 + 2
  + 2 + 8 short processes); it runs only on a change, never on a timer.
- A stream whose port names no endpoint keeps `endpoint: 0`.
- Changing the default, a stream's volume or mute, and a profile were not
  exercised live: they change the author's session. That is `VAL-E`.

## Review fixes (round 1)

- **Slider flood:** the worker now takes everything queued as one batch:
  jobs run in order, refreshes collapse, and the snapshot is read once at
  the batch's end. `Worker::run_keyed` queues a job that a later one with
  the same key supersedes while both wait. `setVolume` uses the key
  `volume:<id>`, and a superseded write still reports `Done`, so `busy`
  settles. `VolumeSlider` sends its first value at once, then at most one
  every 100 ms while it moves, and always the last value when a drag ends.
  Tests: `queued_volume_writes_coalesce_into_the_last` (three writes for one
  id → one write of the last value, one read after the batch, three
  `Done`) and `test_a_dragged_slider_writes_at_most_every_100_ms`.
- **Stalled server:** every tool call has a 2 s deadline. A call still
  running then is killed and reads as `Unavailable`, which the worker shows
  as one notice (it reports a failing read once, not every time). Its
  standard output and error are drained on threads of their own. Tests:
  `a_stalled_tool_is_killed_at_the_deadline` (`sh -c 'sleep 5'` with a
  200 ms deadline) and `a_failing_tool_reads_its_last_stderr_line`.
- **`pw-mon` lifetime:** `WatchHandle` holds the child and kills and reaps
  it in `Drop`. A registry lets `wpctl::stop_monitors()` kill any that are
  left, and `main` calls it through `backend::shutdown()` after `exec()`
  returns. `libc` is not a direct dependency, so no `PR_SET_PDEATHSIG` is
  set. Test: `a_dropped_watcher_kills_its_monitor` (it skips without a
  session). Checked live as well: `timeout 4 snapshot --watch` (killed by
  SIGTERM, so no `Drop` ran) left no `pw-mon` running, and none appeared
  after the next two graph events either (`pgrep -c pw-mon` → 0, 0, 0). A
  `pw-mon` whose reader has died ends on its next write.
- **PipeWire after Cuprita:** `backend::audio` wraps the client in
  `Reconnecting`, which answers `Unavailable` until it connects and tries
  again on each snapshot. When the first connection fails, a thread probes
  `wpctl status` every 2 s; on success it asks the worker to re-read, and
  that read connects the client and starts its watcher. No restart is
  needed. The `Offline` audio stand-in is gone. Test over the fake:
  `audio_connects_once_pipewire_appears`.
- **Unavailable profiles:** `parse_profiles` reads `available`, and
  `card_profiles` drops a profile marked `no` unless it is the one in use.
  Test: `an_unavailable_profile_is_offered_only_when_active`.
- **Stream rows:** `wpctl status` right-aligns ids, so a port is told from a
  stream by an arrow (` > `, ` < `) or by an id that ends to the right of
  the current stream's id. The ports are kept per stream. Tests:
  `streams_with_ids_of_every_width_and_order` (ids of 1–4 digits out of
  order, a port naming no endpoint and a stream with no port both give
  `endpoint: 0`), plus `an_empty_audio_section_reads_as_nothing`.
- **Stream → endpoint:** `wpctl inspect` of a stream carries no
  `target.object` or `node.target` on this host (checked for 116 and 137).
  The client therefore reads `pw-link -lI` once per snapshot and follows
  each stream port's link to the peer node's `node.name`. The nickname
  prefix is only the fallback when no link is found. Tests:
  `links_name_the_peer_nodes` and `links_beat_the_nickname_guess`.
- **Card names:** only a trailing API tag such as `[alsa]` (lowercase
  letters, digits, `-`) is cut. Test: `card_names_lose_only_an_api_tag`.
- **Parser tests:** non-ASCII descriptions and `MUTED` on a source
  (`non_ascii_descriptions_and_a_muted_source`; the test file carries the
  language-contract exemption marker for it), an empty Audio section, and a
  non-zero exit with stderr noise.
- **QML:** the profile-card test waits with `tryVerify`.
- **Profile cards (ruling: accepted):** one card per sound card, which
  deviates from the spec's single profile card. The Repeater's card-id list
  is only re-evaluated when `profiles` changes. The controller only signals
  that change when the choosable profiles differ, so volume, mute and stream
  updates never rebuild the cards and an open menu survives them. Choosing a
  profile rebuilds them, but the menu has closed by then.
