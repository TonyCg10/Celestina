## Limits

- Joining, leaving and forgetting were not exercised live: they prompt
  polkit in its own window and change the machine's saved profiles. That is
  the author's check below.
- The brief's manifest line names zbus with `blocking-api` alone; zbus 5
  refuses to compile without a runtime (`Either "async-io" (default) or
  "tokio" must be enabled`), so `cuprita-core` also enables `async-io`, the
  runtime the cuprita binary already carries. `celestina-rs/Cargo.lock`
  gains that closure.
- The watcher ignores access points' own `PropertiesChanged` (strength on
  every scan); signal bars refresh with the next relevant change
  (device, manager, active connection, access point added or removed,
  profile added or removed).
- A WEP-only access point (privacy flag, no WPA/RSN flags) reads as `Psk`
  and `connect` refuses it before any D-Bus call
  (`NetworkError::wep_unsupported`).
- Airplane mode in `NmNetwork` turns the Wi-Fi radio off and keeps
  Cuprita's own flag in memory only (a restart reads it as off); powering
  Bluetooth off with it is the controller's once the Bluetooth client lands
  (CUP-1-D).
- If the watcher cannot subscribe, the page still re-reads after every
  command but not on outside changes.

## Review fixes (round 1)

- **Wrong passphrase:** a new network is joined with `persist: volatile`; a
  follower thread (`nm/join.rs`) watches the returned active connection's
  `StateChanged`. `join_outcome(state, reason)`: activated → `Keep`
  (`Settings.Connection.Save()` makes the profile persistent); deactivated
  with reason 2 (user) or 3 (device) → `Cancelled`; deactivated with any
  other reason → `Discard` (the volatile profile is deleted, the SSID is
  marked failed and the controller shows `join_failed_message`, the
  product-copy sentence in `error.rs`); anything else → `Pending`.
  A saved profile's join is followed too, without deleting anything.
- **Row states:** a Wi-Fi row takes its state from the active connection
  carrying its SSID (via that profile's `802-11-wireless.ssid`), not from
  `ActiveAccessPoint`: activating → Connecting, activated → Connected,
  otherwise Disconnected, or `Failed` while the SSID's last join failed
  (`wifi_row_state`). Live: the joined network reads `Connected` below.
- **WEP ruling:** kept `Psk` (a new `Security::Wep` would touch the model,
  the list model, the label keys and the QML); `connect` refuses a WEP-only
  route before any D-Bus call.
- **Ids and duplicates:** `wifi:<hex of the SSID bytes>`; one row per SSID
  across every radio, the radio carrying it first, then the strongest
  access point, whose device the activation uses.
- **Radio read failures** are logged (`eprintln!`) and said once in a
  notice while they persist.
- **Debounce** capped at 1.5 s from a burst's first signal (`next_wait`,
  unit-tested). `WatchHandle`'s doc now says its threads end with the next
  signal.
- **Double joins:** the page ignores «Conectar» on a `connecting` row and
  on the id it just asked for until the controller is no longer busy; the
  dialog's «Conectar» disables after one submission.
- **Ethernet `known`:** true only when a saved `802-3-ethernet` profile may
  use the device (no interface name or the same one); Ethernet rows never
  show «Olvidar».
- **`map_error`:** the name rules live in `map_error_name`, unit-tested
  (PermissionDenied → Denied, ServiceUnknown → Unavailable, other → Failed
  with the detail; fdo AccessDenied → Denied).
- **Watcher filtering:** signal bars refresh only with another relevant
  change, never on an access point's own strength update.
