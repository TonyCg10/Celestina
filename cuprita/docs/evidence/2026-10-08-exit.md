## Procedure

Keyboard pass (spec §6):

- **Strip:** `NavItem` took Tab focus on every item, so Tab walked all
  three (the new test failed against it). Only the current item is a Tab
  stop now (`focusPolicy: item.current ? Qt.TabFocus : Qt.NoFocus`); Left
  and Right walk the strip as before; Ctrl+1/2/3 unchanged.
- **Lists:** the network, device and stream lists take one Tab stop
  (`activeFocusOnTab`), the arrows walk them, Enter runs the current row's
  `primaryAction()` (network: join or leave, VPN: switch; device: pair,
  connect or disconnect; stream: mute or unmute) and Space switches a VPN
  row. The current row of a focused list wears `CelestinaRowHighlight`'s
  focus ring.
- **Switches** keep `Switch`'s own Space; **dialogs** close on Esc through
  `CelestinaModalLayer` (already covered by
  `test_escape_cancels_the_pairing`), **menus** through `GlassContextMenu`.

Accessibility pass:

- Every row is `Accessible.ListItem`, named from its `qsTr()` parts joined
  with commas: network — kind (Wi-Fi, VPN or wired), name, state (and
  security), and the bars of four for Wi-Fi; device — kind, name, state and
  the battery when known; stream — the word for application, name, volume,
  and a muted mark when muted.
- The switches (`SettingRow`, the VPN switch) are `Accessible.CheckBox`.
- Both dialogs' cards are `Accessible.Dialog` named by their heading (no
  change needed).

Glass and motion check:

- The glass-canvas guard passes (`Glass-canvas contract: OK` in the
  architecture contract below).
- The dialog fade is `CelestinaModalLayer`'s shared `motionNormal` (200 ms,
  0 under `reducedMotion`); the menus use `motionExit` (150 ms); the row
  plate uses `motionFast`/`motionSlow`. All within 100–500 ms.
- The search spinner's `RotationAnimator` runs only while
  `!CelestinaTheme.reducedMotion`, and `Main.qml` copies
  `CupritaController.reducedMotion` into the theme at start (no change
  needed).

Version: `cuprita/Cargo.toml` and `Cargo.lock` set to 1.0.0 were refused by
`python3 scripts/version_tool.py check` in this worktree (`last history
version for "cuprita" is 0.4.0, source is 1.0.0`, exit 1), so the version was
left as it is: the landing of CUP-1-F with `--kind release` bumps it to
1.0.0 and writes the history row.

`tst_keyboard.qml` adds three tests: the strip is one Tab stop and the next
Tab lands in the page; Enter on the first Bluetooth row connects the paired
headphones and, after Down, pairs the phone; the first device row's name reads its kind, name, paired state
and 80 % battery, and the adapter switch is a check box.

## Fix round 1

- Keyboard reach inside a row: the row buttons (`CelestinaButton`, a Qt
  `Button`) and the sliders (`CelestinaSlider`, `activeFocusOnTab`) are Tab
  stops already. Added: Menu or Shift+F10 on the focused device list opens
  the current row's menu beside its button (`DeviceRow.openMenu()` →
  `popupBeside`); on a focused `VolumeSlider` (streams and endpoint cards)
  Left/Right keep the 1 % step and Shift+Left/Right ask for 5 %, as one
  write. The style's slider handles the arrow first and accepts it, so
  `Keys.priority` cannot reorder the two handlers; `VolumeSlider` instead
  overrides `moveTo` to hold a step until the event ends (`Qt.callLater`),
  and the Shift handler replaces the held +1 with the +5. Menu or Shift+F10
  first brings a clipped current row into view
  (`positionViewAtIndex(…, ListView.Contain)`); the network and stream
  lists open no row menu by keyboard. New tests:
  `test_menu_key_opens_the_rows_menu`, `test_arrows_step_a_volume_slider`.
- Ledger row CUP-1-A is removed: marking it `done` with the AUD-1-P
  inventory is refused by the documentation contract ("inventory already
  belongs to AUD-1-P", and a done row needs a real diffstat). The roadmap
  records it as landed within AUD-1-P; the plan says so above its ledger.
- The stream row's name says the volume as one translation unit with the
  number; the network row's name joins state and security with a comma.
