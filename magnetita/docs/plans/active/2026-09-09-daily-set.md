## Hypothesis

The daemon's plugin modules keep their domain and gain the own wire one
capability at a time, each proven by `magnetita-peer` against the daemon in
a loopback test before the phone touches it; the phone side stays a thin
adapter over the core.

## Tangible outcome

The author's daily set — clipboard, notifications, file share, media,
contacts, SMS, telephony — working end to end on the own wire, with the
Rust half here and the Kotlin half under `magnetita-android`'s `AND-2`.

## Scope

- `MAG-P4-A` — clipboard both ways: the own-wire session drains the shared
  pending slot the desktop watcher fills, writes the phone's text through
  the Wayland adapter, asks for the phone's clipboard on connect; the core
  sends and decodes; the peer carries `--clipboard`.
- `MAG-P4-B` — notifications with actions and replies.
- `MAG-P4-C` — resumable file share both ways under revocation.
- `MAG-P4-D` — media control both ways.
- `MAG-P4-E` — contacts sync and name resolution.
- `MAG-P4-F` — SMS conversations, send, receive, MMS attachments.
- `MAG-P4-G` — call state, mute, answer, hang up; the shell's phone menu.

## Exclusions

- Every Kotlin file: `magnetita-android`'s `AND-2`.
- Commands, input and mirror: `MAG-P5` onwards.

## Build order

1. `MAG-P4-A` through `-D` in any order after `MAG-P3`; `-E` before `-F`
   and `-G`.

## Implementation exit

`magnetita-peer` exercises every capability against the daemon in tests,
the application's JVM tests cover each adapter, and
`scripts/complete-production.sh` passes with both wires.
