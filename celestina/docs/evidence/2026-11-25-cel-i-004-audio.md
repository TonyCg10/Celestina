# Evidence: devices and per-application volume in the volume popup (CEL-I-004)

- **Date:** 2026-11-25
- **Scope:** unit CEL-I-004 on branch `unit/celestina/CEL-I-004` at `c82d355f`:
  B1 `f1d03458` domain; B2 `12d74ba8`, `e9b648cb` worker; B3 `a9da1171`,
  `b59e4aa1` popup; `f83a8d17`, `7ff82d27` row fixes (aligned names, middle
  ellipsis, fixed stream columns); C2 `58c1efb2`, `b5a0183c` collapsible
  sections; `0b7fd302` simplify pass; `c82d355f` final-review fixes; on top of the merges `a8f9292e` and `35c58288` of
  `CUP-WPCTL-STATUS` (which carries `Status::playing`, commit `8a3378f3`).
- **Design change:** on 2026-11-25 the author changed the design (relayed by
  the coordinator): the outputs, inputs and applications lists are collapsible
  sections, folded each time the popup opens. Folded, the outputs and inputs
  lists show only the default device with its check, and the applications
  list only the streams playing now (ports `[active]`) or the "no applications"
  line. Unfolded, every device (at most 8) and every playback stream (at most
  8). Each header is a clickable, focusable row with a chevron (keys
  `level-section` 0, 1, 2). While open, the height changes only by a fold or
  unfold, never by the graph.
- **Resize path (from the C2 report):** a fold or unfold asks the compositor
  for a new size with `SurfaceCtl::resize_popup`, which sends
  `xdg_popup.reposition` with the same stored placement (anchor bottom,
  gravity bottom, so the top edge and the horizontal centre stay and only the
  far edge moves) and the new size. A shell older than `xdg_wm_base` v3 keeps
  the old size and the shell logs a warning; there is no close-and-reopen
  fallback, because a reopen needs a fresh serial and grab. The constraint
  adjustment is slide plus flip, so on an output too small for the unfolded
  card the compositor may move it.
- **Environment:** CachyOS, kernel 7.3.5-2-cachyos, rustc 1.97.1 (8bab26f4f
  2026-07-14, the pinned toolchain), niri 26.04 (8ed0da4). Nested niri on its
  own session bus; the nest window sits on the author's host compositor.
  Nothing ran against the live shell, and PipeWire was never written.
- **Artifact:** debug `celestina` built in a private target
  (`cargo build --locked --bin celestina`, plus `-p celestina-lock -p
  celestina-lock-verify`, `--example fake-mpris-player` and `--offline --example
  fake_system_bus`; all exit 0). Not the production artifact: the landing builds
  that.

## Procedure

Smoke, the OSD phase, from `celestina/`, under `env -i` with only `HOME`,
`PATH`, `XDG_RUNTIME_DIR`, `USER`, `WAYLAND_DISPLAY`, `LANG`,
`CELESTINA_DDC=0`, `CELESTINA_BACKLIGHT=0` and `CARGO_TARGET_DIR`:

```sh
timeout -k 60 2700 sh scripts/smoke.sh --binary <private target>/debug/celestina --only osd
```

Look at the popup, from `celestina/`, one nest on its own bus with no window on
the host monitor, under the same kind of `env -i` plus `XDG_CONFIG_HOME` and
`XDG_STATE_HOME` of its own, a dead `DBUS_SYSTEM_BUS_ADDRESS`, and a scratch
`fakes/` directory first on `PATH`:

```sh
timeout -k 60 150 sh scripts/dev-session.sh --own-bus --monitor none \
    --binary <private target>/debug/celestina --probe <scratch>/probe.sh \
    --once <scratch>/out/run -- --exit-after 40
```

`shell.json` had only `duties.osd` on. The probe ran inside the nest: it waited
for the `celestina-panel` layer, clicked the `volume` piece with a scratch
virtual pointer (`zwlr_virtual_pointer_v1` on the nest's own display, a
throwaway Python client over the raw protocol), took a screenshot with
`niri msg action screenshot-screen`, then clicked the `Salida` header, took one,
clicked the `Entrada` header, took one, clicked the `Aplicaciones` header and
took the last.

The fakes are scratch files, not in the repository: a `wpctl` that answers
`status` with the shape of the author's graph (six sinks, two sources, three
streams: `speech-dispatcher-dummy` 116 with `[init]` ports, `Zen` 150 with
`[active]` ports, and a recorder; the text of B2's `status_text` fixture), answers
`get-volume` with `Volume: 0.50` (stream 150 answers `Volume: 0.80 [MUTED]`),
and for any other call only appends its arguments to a log and exits 0; and a
`pactl` that does nothing, `subscribe` only sleeping.

## Limits

- Not run: the real session, the real PipeWire and WirePlumber, a real
  `pactl subscribe` event, a real default change that sticks, a real mute that
  reads back, a 4K monitor, the keyboard path in a nest (only a unit test),
  a shell older than `xdg_wm_base` v3 (the unit logs and keeps the old size,
  untested live), fractional scales other than the nest's 1.5, the full smoke
  (the landing runs it), the production build, `cargo test --workspace` in this
  task.
- The headers expose no accessible expanded or collapsed state: `celestina-ui`
  has no state hook; only the chevron shows it. Accessibility is not claimed.
- The resize round trip against a real compositor was seen only in this nest;
  the frame between the request and the configure was not examined.
- The look is nested screenshots at one size and one scale with an invented
  graph. Appearance on the author's monitor and sound behaviour are
  `VAL-CEL-I-004`.
- The pointer client and the fakes are scratch tools outside the repository,
  and nobody kept them. The click points (logical pixels of the 628x672 output) were
  563,28 (piece), 360,207 (outputs header), 360,524 (inputs header) and 360,610
  (applications header).
- The capped reader (`System::capped`, B2) has tests with `sh`, `sleep` and big
  outputs only, never with `wpctl`.

## Follow-up

- Two nits of the final review stay open:
  - `graph_of` drops a playback stream whose parser endpoint is 0: an
    unlinked stream, or one whose port nickname prefixes no sink description.
    Fixing it needs the arrow direction from Cuprita's parser.
  - One graph read runs up to nine `wpctl` calls of 2 s each on the worker
    thread, so a hung WirePlumber can hold volume keys for about 18 s. A
    single deadline per graph read would bound it.
- The mute switch of each application row has no text label. The coordinator
  has put it to the author; this unit does not change it.
