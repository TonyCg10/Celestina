## Measured facts (the author's session, 2026-10-17, nothing changed)

- The volume, mute and mic-mute keys run `wpctl` directly; the brightness keys
  run `brightnessctl --class=backlight`, and `/sys/class/backlight` is empty
  here. Brightness on this machine is **DDC only** (`ddcutil` and `/dev/i2c-*`
  exist); `pactl`, `wpctl` and `brightnessctl` are installed.
- Noctalia's `[osd]` table switches off caffeine, dnd, nightlight and
  power-profile feedback; it shows volume, input volume and brightness.
  `/sys/class/leds` has `input2::capslock` and `numlock`.
- The halted shell recorded **two GPU losses with concurrent `ddcutil`
  children on one bus**; its worker held a file lease (`flock`), a 20 s
  timeout per operation, newest-target coalescing and an environment off
  switch. Noctalia also runs `ddcutil`; no lease can cover its processes.

## Decisions (closing spec §7 row C)

1. **Observer: `wpctl` + `pactl subscribe` in one worker, no PipeWire crate.**
   `pactl subscribe` (served by `pipewire-pulse`, which the session runs) is
   the event wire; `wpctl get-volume @DEFAULT_AUDIO_SINK@|SOURCE@` is the
   reading, parsed by the salvaged exact-text parser (no floats). A
   `pipewire` binding needs libpipewire headers/bindgen and a heavy runtime
   (root contract: approval); `wpctl` is the session's own tool. Events are
   settled 30 ms (a wheel burst is one read); if the subscribe child dies the
   worker polls every 2 s and respawns it with a growing backoff (1→30 s).
   Child lines are bounded (4 KiB), the child is killed and reaped on stop.
2. **First reading is a baseline, never an OSD.** The OSD shows only for a
   change after the baseline, and not for a change the slider popup is
   itself driving (the popup shows its value).
3. **Layout.** One `celestina-osd` surface, `Layer::Overlay`, no keyboard,
   empty input region, anchored bottom-centre (Noctalia's bottom-right is a
   look decision of group 2: `osd.position` is a token-like setting with
   `bottom`/`bottom-right`, default `bottom`), on the output niri reports
   focused (fallback: the first output). It is **created on show and
   destroyed after the exit**, so rest costs no surface and no frame. One
   OSD at a time: another kind replaces the content in place; the same kind
   updates the value; either re-arms the timeout (`osd.timeout_ms`, default
   1500, bounded 500–5000). Content: icon, bar of the level, `NN %`; muted
   draws the muted icon and the remembered level. Motion: the contract's
   universal exit and `reducedMotion`. All colours/sizes from `Theme`.
4. **Which OSDs.** Volume, microphone, brightness: each switchable
   (`osd.kinds.volume|microphone|brightness`, default true once the duty is
   on). **Lock-keys OSD is not delivered:** Noctalia has it off, the LEDs
   would need a poll or evdev access, and the author lists no need; recorded
   as an exclusion, addable later from `/sys/class/leds`.
5. **Brightness sources.** sysfs backlight where present (`actual_brightness`
   is `sysfs_notify`-ed: observed with `poll(POLLPRI|POLLERR)` through
   `rustix::event`, no timer); DDC otherwise. **DDC is lazy and gated:**
   no `detect` until the duty is on **and** a brightness consumer exists (the
   `brightness` piece placed in the bar layout, or a `brightness` verb /
   slider use); it then caches the displays. Re-detection on output arrival
   only if a detection already happened, and as one flag, not a queue.
   There is **no periodic DDC read**: the monitor's own buttons are not
   observed (documented gap); a read happens after our own write, and when
   the slider popup opens (one read per monitor, never concurrent).
   `CELESTINA_DDC=0|false` forbids every `ddcutil` call (the smoke and the
   tests always set it).
6. **DDC latency and bounded queue.** One thread owns `ddcutil`; commands
   arrive in a `sync_channel(8)` (refusal beyond it, logged, never blocking
   the loop); it keeps a *pending target per monitor* (newest wins, a burst
   of ten steps is one write) and reads back after writing; each operation
   holds the `flock` lease `$XDG_RUNTIME_DIR/celestina-ddc.lock` and a 20 s
   timeout; at most one child alive; the panel/popup only ever shows the
   read-back (an unread monitor is *unknown*, never 0). The loop never
   waits on this thread.
7. **Verbs** (the keys are rebound by CEL-2-M, not here): `celestina volume
   up|down|set <0-100>|mute`, `celestina microphone mute|set <0-100>`,
   `celestina brightness up|down|set <0-100> [output]` (default: the focused
   output's monitor; unknown output → refusal). Step 5, ceiling 100, as the
   keys' `-l 1.0`. They work with the duty off (they are commands, like
   `launcher toggle`); only the OSD and pieces' presence follow the duty.
8. **Pieces.** `volume` and `brightness` (ids), end zone, in Noctalia's
   order after `tray` in the default layout. A piece with no reading
   returns `None` (no capsule, no DDC touched by merely existing). Scroll =
   step, middle/right click = mute (volume), click = slider popup on the
   existing `xdg_popup` path. The slider is a new `celestina-ui` widget
   (value, drag, keyboard arrows/Home/End, focus ring by `visualFocus`); the
   popup also has the mute toggle and, for volume, the microphone row.
   Pieces only return `PieceAction`s (`Audio(..)`, `Brightness(..)`); the
   app turns them into worker commands. Until the bar has a keyboard path
   (piece contract doc), every action is also a verb.
9. **Switch.** `duties.osd` (`off` default). Turning it on spawns the workers
   and creates nothing visible; turning it off kills the child, joins the
   workers, destroys any OSD surface. Live via the shared `shell.json`
   follower. With the duty off the verbs answer a refusal (`osd` duty off):
   one switch owns every audio and DDC child. (CEL-2-M may revisit this.)

  `/home/toni/CODIGO/isla-spike`.
