## What exists

The shell is a polkit authentication agent behind the `polkit` duty, `off` by
default, switched on in `~/.config/celestina/shell.json` (`"duties":{"polkit":"on"}`).
It registers for the session's own subject, shows a dimmed overlay with a card
that holds the keyboard exclusively, speaks `polkit-agent-helper-1`'s socket
protocol itself and never decides a verdict: a normal reply to
`BeginAuthentication` exists only after the helper's `SUCCESS`.

- **Pure domain** (`celestina-shell`): `polkit.rs` (cookie, request, queue,
  backoff, attempts, the endings and what each replies, the helper-line decoder,
  identity choice, the prompt clock) and `display_text.rs` (the display
  sanitiser).
- **Toolkit** (`celestina-ui`, `celestina-wayland`): `Secret`, `SecretField`;
  a redacting `Debug` for every `InputEvent` that can carry typed text; keyboard
  enter/leave per surface.
- **Providers** (`celestina/src/providers/polkit/`): the bus thread, the
  helper conversation, the session lookup.
- **Loop side** (`celestina/src/polkit/`): the prompt state, the card view, the
  duty's live switch, the non-dumpable window.

those live in `[lib]` (`providers::polkit::tests`, `providers::polkit::helper::tests`),
not in `celestina/tests/` (see the deviations).

The guards of `celestina/tests/polkit_guards.rs` are source scans, not proofs.
They blank comments, cut `#[cfg(test)]` items item by item (not "from the first
`#[cfg(test)]` line to the end": `agent.rs`, `providers/polkit/mod.rs` and
`polkit.rs` carry test seams in the middle of production code), and exclude the
test-only files by name: `providers/polkit/{testing,tests}.rs`,
`providers/polkit/helper/tests.rs`, `polkit/state/tests.rs`,
`polkit/duty/tests.rs`. `the_test_only_exclusion_list_names_only_existing_test_files`
asserts that each of those exists and is declared behind `#[cfg(test)]` by its
parent, and that every other `.rs` file under the polkit directories is
classified, so a new file cannot escape. Each guard has a `scanner_*` test that
feeds the scanner a hostile sample and requires it to report the violation
(and not to report comments, tests or look-alike names such as `unwrap_or` and
`unsafe_code`).

## Spike findings (Task 0)

The full record is [the spike note](2026-10-17-cel-2-i-spike.md). What changed
the implementation:

- Dropping every connection clone does not end a zbus `MessageIterator`.
  Shutdown calls `Connection::close()` on a clone and treats the iterator's
  `Some(Err(..))` (a broken pipe after the buffered messages) as the end. The
  plan's Task 0 step 3 and the spec's "closing" mean `close()`.
- A worker panic does not drop the connection by itself (the reply handles and
  the helper thread hold clones): the bus thread owns a drop guard that calls
  `close()` (N-23, F-23).
- With no object server nothing answers `Introspectable` or `Peer`; N-13 is
  asserted as "nothing but the agent's own methods is answered".
- A genuine `NameOwnerChanged` has the bus driver as sender and no
  destination; a forged unicast has a peer as sender and a destination. The
  unfiltered iterator also sees method returns and the driver's unicast
  `NameAcquired`, so the recogniser's destination check is load-bearing
  (`bus_signal`).
- The non-dumpable window makes `/proc/<pid>/fd` root-owned and `environ`
  unreadable, not the directory itself; `cmdline`, `stat` and `cgroup` stay
  readable. Harmless for the shell (U-11).
- U-1 (the agent interface is reachable only by `polkitd` on this host),
  U-2 (`Error.Cancelled` is `POLKIT_ERROR_CANCELLED`, recorded by polkitd as
  "dismissed"), U-5 (hibernation is not configured), and U-6 (the toolkit has
  no AT-SPI) were closed consistent with the spec.

## Deviations from the plan and the design

To be reported to the author; none patches the spec.

1. **The display sanitiser is polkit-local.** Task 1 delivered only the
   `NameOwnerChanged` recogniser (`celestina/src/bus_signal.rs`, the tray
   delegating). The sanitiser could not move to a shared owner inside a
   `celestina:` unit (`celestina-core` and `fluorita-core` are other projects'
   commit roots), so it lives in
   `celestina-rs/crates/celestina-shell/src/display_text.rs`, whose head names
   `fluorita-core::metadata::claimed_text` as the reference set (a superset is
   required by design §6.2 D, and a test asserts it). This is the second option
   of design Q14, with the reason written down. Converging the two is a later
   suite unit.
2. **Spike overrides** (above): `close()` instead of dropping clones, the drop
   guard, no introspection requirement, the corrected `/proc` wording.
3. **Task 4: the request table lives provider-side, behind a mutex.** The
   cookie never enters `Message`; the loop holds a request id and asks the
   agent (`AgentPort`) for the text and the helper input. A reply thread sends
   the replies, so no reply is written from the loop thread.
4. **Task 5: `HelperEvent` has no `Success` or `Problem` variants and the
   answer path is the `Answer` trait.** Success and failure are `Ended(..)` with
   an `Ending`, and the helper is generic over what it writes so a test can
   probe the drop of the secret.
5. **Task 6.** The card's glyph is the suite's `key` icon, not a lock
   (`celestina-style/icons` has no `lock.svg` yet). `MAP_TIMEOUT` bounds a card
   the compositor never configures (F-6). The scrim is a new `Role::Scrim`
   token in `celestina-paint`. Notices are posted through a new
   `NotificationsCommand::Post`. The island's `button_filled` became
   `pub(crate)` for the card's buttons.
6. **Task 7.** A notice (the proof failure, the cool-down) is lost while
   another program holds `org.freedesktop.Notifications` (Noctalia): the
   shell posts the notice to its own server, which is not running then, and
   there is only a tracing line instead. The request is still cancelled, so
   the failure is closed, but the person is not told. See VAL-CEL2-POLKIT-LIVE.
7. **Tests live in the crate, not in `celestina/tests/`.** The plan named
   `tests/polkit_helper.rs`, `tests/polkit_prompt.rs` and `tests/polkit_duty.rs`
   for the behavioural tests. They need private seams (`connect_at`, the fake
   host and agent, the log capture), which an integration test cannot reach
   without widening the public API, so they sit next to the code:
   `src/providers/polkit/{tests.rs,helper/tests.rs}`, `src/polkit/{state,duty}/tests.rs`.
   `tests/polkit_duty.rs` holds the one check that needs the manifest (S-8),
   and `tests/polkit_guards.rs` holds the guards.
8. **Task 8 adds tests the plan did not list** because the spec's `T` for N-1
   asked for a `TRACE` capture through a conversation: the two log-capture tests
   under N-1, and the guards `n01_secret_has_no_derive_and_implements_only_default`,
   `n04_…`, `n14_…`, `n20_…`, `n22_…`, which close items the plan's guard list
   did not name.
9. **The wrong-password check of the live row** is "once wrong, then right"
   (see the faillock note): `MAX_ATTEMPTS` is 2 and the plan's "wrong twice"
   would spend the last attempt of a prompt on this host.
10. The constants of §6.4 and the defaults of §12 (Q1 `Failed` for faults, Q3 no
    `details`, Q4 constants, Q8 no input method, Q11 refuse when the own uid is
    not offered, Q12 no paste) are the proposals, implemented as written; the
    author has not confirmed them.
11. **F-18 says "done" in the design; the card closes without a word.** The
    design's F-18 reads "wipe, close, say 'done'". The card has no such text and
    the shell has no copy for it: polkitd decides on its own state, and the
    person sees the program that asked go on or fail. Recorded for the author;
    adding the word is a `copy.rs` string and a notice, not a change of rules.
12. **The helper's test seams are compiled in production.** The design (§6.3
    N-16) asks for seams "only under `#[cfg(test)]` or a test-only feature".
    `connect_at`, `spawn_with`, `Trust` and `Timing` are the production
    implementation with their parameters left open: they are private or
    `pub(crate)`, the production `connect` passes the constants, and the guard
    pins the one path literal. Putting them behind `cfg(test)` would mean a
    second implementation of `connect` for tests, which proves less. Recorded
    for the author.
13. **The nested-niri item of §10.1 did not run.** "The prompt maps, holds the
    keyboard, closes on Escape and denies on focus loss, against the private
    bus" needs a fake polkitd and a fake logind on the nest's bus; they exist
    only as in-process test fakes. `scripts/smoke.sh` ran its polkit nest (the script's last since the merges of
    2026-10-22; the ninth before them: the
    dead system bus: unavailable, never registered, no panic); mapping a real
    prompt is the live row's step 1.
14. **The agent's bus thread has a reading thread.** The design (§4.2) has one
    blocking iterator read by the bus thread. It is still one reader, in arrival
    order, but a thread of its own (`polkit-read`) takes the messages out from
    the start and keeps only the ones the bus thread can act on, because a full
    iterator queue stops zbus's socket reader and any local user may unicast
    signals to the agent (review I-2). ADR 0021 decision 22 says so.
15. **Every bus call of the agent has a 20 s timeout** (it was 3 s). The
    registration may start polkitd, and a registration that timed out can
    neither be known to have happened nor be repeated; a timeout is
    `Unavailable`, never "absent" with a retry. The design gives no figure.
16. **The loop does not wait for the agent's threads.** The design §4.2 has the
    agent "joined" on stop; the loop now hands a finished prompt's helper thread
    and a switched-off agent to reaper threads (N-22), and the next agent waits
    for the reaper before it registers.

### Residuals

What was decided not to fix, with the reason.

- **R-1.** `ReplyHandle` holds the call's whole `Message` until it replies, so
  the cookie's bytes sit in zbus's buffer, unzeroized, as long as the request
  lives (and zbus's receive buffers hold them before that). Storing only the
  header needs an owned header type zbus does not give for `reply`; the cookie
  is worth something only while the request is pending (design §6.2 C).
- **R-2.** The reading thread's queue (64) fills only with polkitd's calls and
  the bus driver's broadcasts about polkitd. A flood of *method calls* to the
  agent's path would still fill it on a bus whose policy lets any peer call the
  agent; the system bus's policy does not (spike U-1), and the agent answers
  those `AccessDenied`.
- **R-3.** The prompt's deadlines (keyboard proof, focus grace, idle cap, map
  timeout) are looked at when a frame callback arrives. With the output switched
  off or the surface hidden none arrives and a prompt ends only when polkitd
  cancels it or the person acts; nothing is granted either way. A loop timer
  independent of frames needs the runtime's loop handle, which the app does not
  keep; recorded in `VALIDATION.md`.
- **R-4.** `Queue::drain` does not set the time of the last end, so
  `REGRAB_GAP` is not applied after a polkitd owner change. It needs a clock
  argument on the pure domain's `drain`.
- **R-5.** If polkitd restarts within milliseconds of the agent's registration
  call, the second registration can be answered "already exists" and the agent
  stays `Refused` although it works. The person's off and on retries.
- **R-6.** A key held through the guard window repeats with the serial of its
  press, which is newer than the enter, so its repeats are accepted when the
  window ends. It needs a person holding a key the moment a card appears.
- **R-7.** A click on Cancel inside the guard window denies (and counts as a
  dismissal). The design asks for the guard window for keys only.
- **R-8.** Two prompts that each fail twice inside the account's
  `fail_interval` can lock the account (`deny = 3`); one prompt cannot.
- **R-9.** A call to the agent's path that is not one of its two members is
  dropped, so its caller waits for its own timeout (N-13 asks for exactly that
  silence).
- **R-10.** The `XDG_SESSION_ID` hint inherited from a user service that
  outlived its session can disagree with `Display` and make the agent
  `Unavailable` with the reason shown (fails closed). A bus that ends is
  reported to the loop with the ending `OwnerChanged`, the same row as F-8.
- **R-11.** If the operating system refuses the thread for an agent's reaper
  (`Reaper::spawn` fails), the agent is dropped on the calling thread and
  `PolkitAgent::drop` joins within `STOP_WAIT` (up to about 4 s), which the
  loop-side rule N-22 forbids; the reaper it returns is empty, so the next
  agent does not wait for the earlier teardown either. It needs thread
  exhaustion; the join is bounded and the next registration fails closed
  (`Refused`). Degrading to `Connection::close()` without a join would hide
  the same exhaustion behind a second path.
- **R-12.** The shell's exit (`PolkitDuty::drop`) waits for the latest reaper
  without a fixed bound of its own. Each reaper is bounded by two `REAP_WAIT`
  joins (about 10 s) and they run concurrently, so a chain does not add up; if
  the helper thread of `Worker::join_within` cannot be created, that join
  falls back to an unbounded one. Needs thread exhaustion plus a hung teardown.
- **R-13.** A registration that times out (20 s) but that polkitd accepts late
  leaves the agent serving requests while the state says `Unavailable`, which
  is terminal. Nothing is granted by it and a request is still shown and
  answered normally. Closing the connection on that path would be a change of
  the registration state machine (`RegistrationState` is terminal on purpose,
  decision 1) and is not made here.
- **R-14.** The reading thread admits a method call to the agent's path,
  interface and member from any sender into its queue of 64; the bus thread
  checks the sender on the header afterwards. Whether a stranger can send such
  a call depends on the system bus policy, which on this host
  (`/usr/share/dbus-1/system.d/org.freedesktop.PolicyKit1.conf`) lets only
  `polkitd` send to the agent's interface. With a laxer policy about 128 sends
  during the registration would exhaust it (`Unavailable`, fails closed). The
  same property as R-2; a copy of the owner kept by the reading thread would
  remove the dependence and is a later change.
- **R-15.** A panic of the reading thread is reported by the bus thread's
  guard as "the bus connection ended" with the ending `OwnerChanged`, and the
  cause is lost. It fails closed.
- **R-16.** `BusGuard::drop` joins the reading thread without a bound; it
  relies on `Connection::close()` ending zbus's iterator, which zbus documents
  and the spike (Task 0) checked. `bus_signal::name_owner_change` logs one
  `debug!` per forged unicast `NameOwnerChanged`: at debug level a local flood
  fills the journal, as before these fixes.

## Gaps

What no test enforces, stated rather than invented.

- **N-1, the full capture.** The `TRACE` capture runs through the agent's
  handling of a request (the cookie) and through a complete helper conversation
  (the typed answers and the cookie). No capture runs through the loop state
  with a typed key and the real toolkit input path; what covers it is the
  redacting `Debug` of `InputEvent` (the `runtime.rs` log site prints `?ev`),
  the consumption of the event by `SecretField::handle`, and the absence of any
  `tracing` macro on a line that names the secret (`n05_lines_that_name_the_secret…`).
- **N-6 at the state level.** No test reads the bytes of the state's `Secret`
  after each §6.4 terminal event; wiping is by ownership ending, checked on the
  toolkit (`secret_clear_zeroes_the_used_length`,
  `field_wipes_the_secret_when_the_keyboard_leaves`), on the helper thread
  (`the_secret_is_dropped_after_the_write_and_on_every_error`) and on the state
  through its observable (`field_state` is `Empty`, the helper cancelled). A
  byte probe needs a test-only accessor in `celestina-ui` that the product
  crate cannot reach; adding one widens the toolkit's API for a test.
- **N-24 and N-25 with a compositor.** The keyboard proof, the guard window and
  the loss are tested against a fake host and the toolkit's enter/leave
  events. A real `wl_keyboard.enter` on a real layer surface did not run: it is
  the live row's check.
- **N-22 is a heuristic.** The guard looks for blocking calls by name in the
  loop-side modules; it cannot see a blocking call behind a function. The
  review found one that way (B-1); what holds the property now is the timing
  tests of the N-22 row, which fail when the loop waits.
- **S-5, accessibility.** The toolkit has no AT-SPI; the field exposes only its
  name and whether it holds something, and nothing is claimed.
- **The secret in the toolkit's freed key text** (sctk and xkb allocate and
  free it unzeroed) is a documented residual (design §6.2 C), not enforced.
- **The residual windows named in the design** (a second program with the
  same uid, a virtual keyboard, a screen capture of the card) are out of scope
  of the unit and listed for the author in `VALIDATION.md`.
