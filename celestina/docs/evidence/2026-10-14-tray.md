## Deviation from the plan (author ruling)

The plan builds the tray on the `system-tray` 0.8 crate. The author ruled
that it is not used, and neither is tokio. The StatusNotifierWatcher, the
host, the item client and the DBusMenu client are our own code over `zbus` 5
blocking, which the shell already depends on. The reasons: `system-tray` pulls
in tokio; it requests the watcher name queued, where the design (§5.6) needs a
`DoNotQueue` claim that records the owner when the name is taken; and it does
not bound a pixmap before copying it, where a bus peer is hostile and every
size, depth, count and rate must be bounded. No dependency was added and
`Cargo.toml` is unchanged.

## Known limitations

- A submenu opens on a click, Enter or Right, not on hover: a hover-opened
  submenu would rely more often on the grab serial below, which is unverified.
- The nested popup grabs with the serial of the last input
  (`GrabSerial::current()`); for a submenu this is the serial of the press that
  opened the parent. xdg-shell wants a serial valid for the seat, and niri
  accepts a reused one in practice, but it is unverified against a live niri.
- A menu level taller than 640 px is cut: entries past the cap are not built,
  and there is no scrolling. The Tray page lists at most 24 rows; the rest are
  unreachable on the page.
- A republished level that grew or shrank asks the compositor for its new
  size (`xdg_popup.reposition` with the placement it opened at, through
  `SurfaceCtl::resize_popup`), once per wanted size, and meanwhile builds only
  the rows its popup holds: none is clipped and the keyboard reaches none
  outside the card. The new size comes with the configure that follows; on
  an `xdg_wm_base` older than version 3 (niri binds 6) the popup keeps its
  size and the rows past it stay unbuilt until the chain is reopened. The
  reposition is unit-tested at the queue and the level; the configure
  round trip itself needs the nested niri (VAL-CEL-POPUP).
- `celestina-ui` has no accessible-name API: rows are focusable with the
  title as visible text, and nothing is exposed to AT-SPI.
- Radio entries are drawn like check entries (the model keeps only
  `toggle: Option<bool>`); an unchecked one shows nothing.
- `Activate`, `SecondaryActivate` and the context request carry the position
  `(0, 0)`: `TrayCommand` has no pointer position. A left click, Enter and
  Space always send `Activate`, also for a menu-only item (`ItemIsMenu` is
  not read); a right click on an item without a menu does nothing.
- Item properties are read one by one (six round trips per item),
  deliberately, so that neither `IconPixmap` nor a text property ever passes
  through a generic `Value`: a text reply is refused past 4 KiB or when its
  variant is not an `s` or `o`. zbus still buffers a received message
  itself, up to its 128 MiB message limit, before the body is looked at;
  that transient is zbus's and not bounded here. A silent peer costs 1 s per
  call, a slow one at most 0.9 s plus one call's timeout per read (1.9 s,
  under the 2 s the shell's exit waits for the host), then a 30 s back-off;
  an honest item must answer its six property calls within 0.9 s in all or
  it counts as unresponsive too. A peer signalling changes is re-read at most
  once a second, and the last item read stays listed in its place until the
  re-read replaces it (or the item leaves, or its object is gone); a slow
  re-read keeps it too.
- A well-known name whose owner changes more than 8 times within one 100 ms
  window is "churned": its history is dropped and the host asks the bus who
  holds it now, so a registration released and re-registered inside such a
  burst may be kept where the protocol would have dropped it until the
  re-registration. An honest peer never gets there.
- zvariant decodes a reply of up to 1 MiB before the menu walk's node budget
  applies, and its own container depth limit refuses deep layouts (no menu);
  verified over the wire to about 40 levels.
- A menu is followed (re-published on a layout or property change, coalesced
  by the 100 ms read window) from `OpenMenu` until the page's `CloseMenu`;
  the 8-menu bound on followed menus covers a close the page never reported.
- `IconThemePath` is not read: an item whose icon name is private to a
  directory of its own draws its pixmap when it publishes one, else the
  fallback icon. A theme lookup per named item runs on the loop's thread
  when the list changes (at most once a second per item), not per frame.
- The horizontal scroll sign follows Qt's `angleDelta` (positive for a tilt
  to the left), by reading of QtWayland, which negates both axes; it is
  unverified against a real item (VAL-CEL-NOCTALIA).
- Large single pixmaps are not downscaled: anything above 256 px a side is
  dropped and the item shows its theme icon or the fallback.
- On a removal the watcher emits `StatusNotifierItemUnregistered` but no
  `PropertiesChanged` for `RegisteredStatusNotifierItems`.
- `dev-session.sh` without `--own-bus` runs the shell on the session bus,
  where it claims the watcher name if it is free at that moment.
- At most 4 items per sender and 64 items in all; `IsStatusNotifierHostRegistered`
  is always true; a foreign host is recorded and nothing else is done with it.
- Each output's Island uploads its own copy of an item's pixmap; textures are
  not shared between Islands.
- A menu answer that arrives after the page closed is dropped, and a late
  `Menu` for a stale request is ignored unless it matches the pending item.
- The popup's final position from the compositor is logged but not delivered to
  the shell, so a popup cannot compute its own bounds exactly; the product
  asks for `TopRight` or `BottomRight` and accepts the compositor's flip.
- `PixmapId`'s field is public in `celestina-paint` now (a made-up id draws
  nothing).
- `tray::test_bus` repeats the private-bus recipe of `bus.rs`'s tests, which
  this unit did not edit.

## Review findings and fixes

A read-only review of the branch at 75e2e9e8 found one critical and eight
important findings and a list of minor ones. One fix wave addressed them,
with the tests below written first where the finding was testable:

- **C1, text properties decoded through `Value`.** A `Title` holding a
  large byte array would have decoded one `Value` per byte. `item::text_of`
  now refuses a reply past `MAX_TEXT_BODY_BYTES` (4 KiB) and decodes only a
  variant whose signature is `s` or `o`, typed; the pure test
  `text_properties_are_decoded_typed_and_refused_by_type_and_size` and the
  private-bus test `a_title_that_is_a_large_byte_array_reads_as_an_empty_title`
  (a 256 KiB `ay` title, read as empty) cover it.
- **I1, forged `NameOwnerChanged`.** `recognise` accepts the signal only from
  `org.freedesktop.DBus` and only as a broadcast; a forged and a directed one
  are tested ignored.
- **I2, English on the Tray page.** The watcher returns `NameHolder {
  unique, comm }` and `copy::tray_owner(unique, comm)` composes the Spanish
  line ("Otro programa atiende la bandeja: noctalia (:1.42)"). `NameOwner.tray`
  is now `Option<NameHolder>`; CEL-1-F should give `notifications` the same
  shape and compose its line in `copy.rs` the same way.
- **I3, unbounded refresh.** One item's read gives up past
  `ITEM_READ_BUDGET` (1.5 s), a pass reads for at most `READ_BUDGET` (300 ms)
  and carries the rest to the next pass, the queue is drained and the
  shutdown flag read before every item read, and an item is re-read at most
  once per `MIN_REREAD` (1 s) after a signal. The private-bus test
  `a_slow_peer_delays_neither_commands_nor_the_shutdown` (a peer answering
  each property in 900 ms) fails without the per-item budget (the command
  took 5.4 s) and passes with it (1.7 s); the shutdown joins within 3 s.
- **I4, signal amplification.** The host tells the signal worker the
  (name, path) pairs and names it serves; a signal from anyone else is
  dropped before the 256 bound, so only the tray's own peers can overflow it.
  The fallback that re-read everything a connection serves on a signal from
  an unregistered path is gone. Tested in
  `signals_of_strangers_are_dropped_before_the_bound`.
- **I5, pokes in the command queue.** `Poker` queues one `Poke` at a time
  (an atomic flag the host clears when it takes it), so a burst never takes
  the page's 64 slots; tested in `pokes_take_one_queue_slot_however_many_come`.
- **I6, submenu `AboutToShow`, republished menus, `CloseMenu`.** The chain's
  levels share one `MenuModel`; a level is the subtree at its path of entry
  ids and rebuilds its rows (keeping the keyboard's focus by row key) when
  the model's generation changes. Opening a submenu asks the host for
  `AboutToShow(item, entry)` through the `AskSink` the app hands the chain;
  a submenu that arrives empty is awaited and opens once the republished
  model carries its entries. A `Menu` for the open chain's item replaces the
  model and redraws the root and every chained popup
  (`RuntimeCtl::popup_surface`, new). When the root popup closes the app
  sends `CloseMenu(item)` and `DbusMenu` stops following it (tested in
  `a_closed_menu_is_not_followed_any_more`). Pure tests cover `level_at` and
  `replace_level`; the popups themselves still need the nested niri
  (VAL-CEL-POPUP).
- **I7, unresolvable icon names.** `TrayItem` carries `icon_name` and the
  best `pixmap` (always read, bounded as before); `IconCache::rows` draws
  the theme icon when `Painter::has_theme_icon` (new) finds it, else the
  pixmap, else the fallback, with the lookup at list time. Tested in
  `a_name_the_theme_lacks_falls_back_to_the_pixmap_then_the_fallback_icon`.
  `IconThemePath` stays a known limit (above).
- **I8, keyboard activation.** Enter and Space activate the item as a click
  does; the Menu key and Shift+F10 open the menu (unchanged). The Island test
  and VAL-CEL-POPUP say so.
- **Minor fixes.** A `Menu` is matched to the pending request before an empty
  menu clears it (M1); a tray menu opens only while the Tray page is shown
  (M2); the horizontal scroll is negated with the vertical, as QtWayland's
  `angleDelta` is, and listed for verification (M7); the private test bus
  runs on its own configuration without a service directory (M8); Unicode
  format characters (bidi controls, zero-width characters, the byte order
  mark, tags) are dropped from titles and labels with the controls (M10,
  tested); the first level's gap comes from `theme.spacing.sm` (M12).
- **Not done.** I9, the rebase onto `main`, is the author's at landing. M3
  (pixmap bytes through the unbounded loop channel, compared on the loop),
  M4 (downscaling large pixmaps), M5 (`ItemIsMenu`), M6 (`PropertiesChanged`
  on removal), M9 (`dev-session.sh` default bus), M11 (the deep clone per
  `node`, bounded by depth 4 and the 1 MiB body), M13 (event batching of a
  dismissal with an open submenu) and the accessible-name limit remain as
  listed under the limitations. Shift+Enter for `SecondaryActivate` was not
  added: `UiEvent::Activate` carries no modifiers.
- **Checks after the fixes:** `cargo fmt --all --check`, `cargo clippy
  --workspace --all-targets --locked -- -D warnings` and `cargo test
  --workspace --locked` (179 in the library) exit 0, as do
  `check-architecture-contract.sh`, `check-language-contract.py`,
  `check-documentation-contract.sh` and `version_tool.py check`.

## Second review round

The re-review of the fixes above found one new defect and two findings only
partly fixed; this round closes them, tests first.

- **N1, an item vanishing while its re-read waits.** `Entry::invalidate`
  cleared the item, so an item signalling within `MIN_REREAD` of its read
  (every item at startup, every blinking one) left the list for up to a
  second and the rows below moved up under the pointer. The entry now keeps
  the last item and a `stale` flag; the item is cleared only when it leaves
  (`Gone`, owner lost) or its object is gone (`NotServed`), and a slow
  (`Unresponsive`) re-read keeps it. Tests: the pure
  `an_invalidated_entry_keeps_its_item_until_it_is_read_again` and the
  private-bus `an_item_that_signals_stays_listed_at_its_index` (two items,
  the first signals right after its read: every list published until the
  change shows has both, the first at index 0), seen red against the old
  clearing.
- **I4, signal amplification by a registered peer.** `MenuChanged` is
  recorded only for a known (owner, menu path) pair (`Pending.known_menus`,
  from the items' `Menu` property) and once per pair; an item's
  `LayoutUpdated` from paths it did not publish counts for nothing. A known
  name's owner history is bounded per name (`MAX_OWNER_CHANGES_PER_NAME`,
  8); past it the name is churned and resolved through the bus (above). With
  every list deduplicated against a known set bounded by the watcher's 64
  items, the overflow that re-read every entry is gone, and so is
  `check_every_owner`. Tested in `signals_of_strangers_are_dropped_before_the_bound`.
- **I6, a republished level larger than its popup.** The runtime gained the
  smallest additive API that fits the protocol: `PopupQueue::resize`,
  `SurfaceCtl::resize_popup(size)` and `PopupOp::Resize`, which reposition
  the popup with the placement kept on its entry; `LevelCore::resize_wanted`
  asks once per wanted size and `LevelCore::fit` builds the rows for the
  height the popup has (`level_view(theme, level, height)`,
  `drawn_len(theme, level, height)`). Tests:
  `queue_hands_out_increasing_ids_and_keeps_order` (the resize op) and
  `rows_past_the_popups_height_are_not_built_and_the_level_asks_for_room`
  (the keyboard wraps within the rows built, every row once the room is
  there, a fraction of a pixel asks for nothing). The limit above records
  the old-shell case.
- **R1, one read past the exit's wait.** `ITEM_READ_BUDGET` is 900 ms, so a
  read is at most 1.9 s with the call that overran it, under `JOIN_WAIT`
  (2 s); the slow-peer test now joins within 2 s and asserts the sum. The
  cost is R3's: an honest item slower than 150 ms per property call counts
  as unresponsive (recorded above).
- **Not done.** R2 (a longer back-off after a slow read), R4-R12 and I9 stay
  as recorded; R8's lost `CloseMenu` is bounded by `MAX_FOLLOWED`.
- **Checks:** `cargo fmt --all --check`, `cargo clippy --workspace
  --all-targets --locked -- -D warnings` and `cargo test --workspace --locked`
  (182 in the library, 49 in `celestina-wayland`) exit 0, with the private-bus
  tests running; the root guards as before.
