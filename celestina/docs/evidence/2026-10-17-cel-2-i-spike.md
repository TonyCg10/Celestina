## Result

### Step 1: the precondition holds

`AGENTS.md` at `a3d5408e` carries the CEL-2-I entry that lists
`celestina-qt/src/polkit{agent,conversation,promptcontroller}.cpp` and
`celestina-qt/src/polkitconverse/main.cpp` as read-only reference for
`celestina/src/providers/polkit` (line 86). The plan's literal pattern
`polkitagent` does not match that brace spelling; the entry is the one spec §8
asks for.

### U-1: the agent interface is reachable only by `polkitd` — closed, consistent with the spec

- `org.freedesktop.PolicyKit1.conf` has three rules: user `polkitd` may own
  `org.freedesktop.PolicyKit1`; the default context may send to that
  destination; user `polkitd` may send on
  `org.freedesktop.PolicyKit1.AuthenticationAgent`. The comment above the last
  rule says "uid 0" but the rule is `user="polkitd"` (`polkitd` runs as user
  `polkitd`: `ps -o user -C polkitd`).
- `system.conf` denies every `method_call` by default (`<deny send_type="method_call"/>`),
  allows signals, and its `root` policies concern only `org.freedesktop.DBus`
  interfaces. There is no `/etc/dbus-1/system.conf` and `/etc/dbus-1/system.d`
  holds only `org.linuxtv.Zbar.conf`.
- The parsing script found no `root` or default rule that allows method calls
  to everything, no `send_destination="*"`, and the only
  `send_interface="org.freedesktop.PolicyKit1.AuthenticationAgent"` rule of the
  whole tree is the `polkitd` one. Other `root` interface rules concern their
  own interfaces (bluez, iwd, NetworkManager agents, and the like).
- Conclusion: on this host, a method call to the agent's unique name is
  allowed for `polkitd` and denied for everyone else, root included. The
  header check of N-12 is the second wall, as designed. Signals are **not**
  restricted (`<allow send_type="signal"/>`), so the forged unicast
  `NameOwnerChanged` of threat A reaches the agent; the spike below shows it
  arriving.
- Limit: this reads the policy files. It does not exercise dbus-broker's
  enforcement (the spike bus is deliberately permissive).

### U-2: `Error.Cancelled` is `POLKIT_ERROR_CANCELLED` — closed, consistent

`src/polkit/polkiterror.c` (tag `127` and `main` are byte-identical, 1832
bytes) lists `{POLKIT_ERROR_CANCELLED, "org.freedesktop.PolicyKit1.Error.Cancelled"}`
(and `…Error.Failed`, `…Error.NotSupported`, `…Error.NotAuthorized`).
`polkitbackendinteractiveauthority.c` at `127`, lines 2061 to 2062, sets
`was_dismissed = TRUE` when `error->domain == POLKIT_ERROR && error->code == POLKIT_ERROR_CANCELLED`,
and lines 798 to 799 turn that into `polkit.dismissed = "true"` in the details.
The spike also shows that `Connection::reply_error` with that error name
reaches the caller as a `MethodError` carrying exactly that name.

### U-5: hibernation is not configured — closed

`/sys/power/state` is `freeze mem disk`; `/sys/power/resume` is `0:0`;
`/sys/power/disk` is `[platform] shutdown reboot suspend test_resume`. The
kernel command line has no `resume=` and no `resume_offset=`; mkinitcpio's
`HOOKS` are `base systemd plymouth autodetect microcode kms modconf block keyboard sd-vconsole filesystems`
(no `resume` hook; the `systemd` hook would read `HibernateLocation` from EFI,
and no such variable exists); `/etc/systemd/sleep.conf` is entirely commented
out; the only swap is `/dev/zram0` (62.4G, priority 100), so there is no disk
swap an image could be written to. Secret pages cannot reach disk through
hibernation on this host as configured.

### U-6: the Rust toolkit has no AT-SPI — closed

`rg -n -i 'atspi|accesskit'` over `celestina/Cargo.lock`, `celestina/crates`,
`celestina/Cargo.toml` and `celestina/src` printed nothing (exit 1). The only
mentions in `celestina/` are prose: the archived island plan ("accessibility
through `accesskit`: later") and the tray evidence ("nothing is exposed to

### U-11: what the non-dumpable window changes — closed, and it differs from the spec's wording

Shell side: no portal client code in the shell (the `rg` for
`xdg-desktop-portal`, `org.freedesktop.portal`, `ashpd`, `document-portal`
printed nothing). The `/proc` readers in the shell read **other** processes'
files (`celestina/src/providers/notifications.rs:394`, `/proc/<pid>/comm`),
which a non-dumpable window of the shell does not affect. `celestina-core`'s
`xdg.rs` reads `/proc/self/status` (`effective_uid`) and nothing in the shell
calls it. Nothing in the shell reads `/proc/self/fd`, `/proc/self/environ`,
`/proc/self/exe` or uses `procfs` helpers.

Measured on 7.2.10 (script `dump.py`, `PR_SET_DUMPABLE` 0, then probes):

| Path | before | after, by the process itself | after, by a same-uid child shell |
|---|---|---|---|
| `/proc/<pid>` (directory owner) | user | **still the user** | still the user (`dr-xr-xr-x toni`) |
| `/proc/<pid>/fd` (directory owner) | user | **root** (listing it by itself still works) | listing denied |
| `status`, `stat`, `cmdline`, `comm`, `cgroup`, `mountinfo` | readable | readable | `stat`, `cgroup`, `cmdline`, `mountinfo` readable |
| `maps`, `exe`, `cwd`, `root/` | readable | readable | `exe`, `root` denied |
| `environ` | readable | **denied, even to the process itself** (EACCES) | denied |

An `exec`ed child of a non-dumpable process is dumpable again (`dumpable=1`
in a Python child; `fs.suid_dumpable` is 2 and is not involved).

Consequences to carry into S-9 and its test:

- The spec's phrase "it changes `/proc/<pid>` ownership for the window" is
  imprecise on this kernel: the directory stays user-owned; the entries that
  turn root-owned or denied are `fd`, `environ`, `exe` and `root` (the
  last two denied to other processes).
- Tools that inspect the shell by `/proc/<pid>/{environ,exe,root,fd}` lose
  access during a window (debuggers, `lsof`-style listings, a portal's
  sandbox check if the shell ever becomes a portal client); the files
  polkitd and systemd use (`stat` for the process start time, `cgroup` for
  the session) stay readable, as the child-shell probe shows.
- The shell must not read its own `environ` or `/proc/self/fd` while a window
  is open. Today nothing does. A guard test for the polkit modules can state
  that.
- Children spawned in the window are not covered by the window (they are
  dumpable). §5.1 already closes the launcher while a prompt is up.

### Step 3: the zbus facts, from the vendored source (`zbus 5.19.0`) and the spike

1. **`Builder::system()` honours `DBUS_SYSTEM_BUS_ADDRESS`.**
   `src/address/mod.rs:92-95` reads the variable and falls back to
   `unix:path=/var/run/dbus/system_bus_socket`; the spike's
   `Builder::system()` connected to the private bus through it. `blocking::connection::Builder::system()`
   (`src/blocking/connection/builder.rs:42`) delegates to it. Confirms spec
   fact 15.
2. **`blocking::MessageIterator` over a `Connection`.**
   `MessageIterator::from(&Connection)` (`src/blocking/message_iterator.rs`)
   is `MessageStream::from(conn.clone())`, which activates a clone of the
   connection's **unfiltered** queue (`src/message_stream.rs`, `From<Connection>`).
   It yields **every** message the bus delivers to the connection, in arrival
   order: the unicast `NameAcquired` signal and the replies to the
   connection's own `Hello`/`AddMatch`/`GetNameOwner`, then the calls and
   signals. The spike's first six items, in order, were `NameAcquired`
   (signal, sender `org.freedesktop.DBus`, **destination `:1.0`**), two
   `MethodReturn`s, a broadcast `NameOwnerChanged`, the forged unicast
   `NameOwnerChanged`, and the method call. A `MethodCall`'s header as the
   iterator sees it: sender `:1.1`, destination `:1.0`, path
   `/org/celestina/PolkitAgent1`, interface
   `org.freedesktop.PolicyKit1.AuthenticationAgent`, member
   `CancelAuthentication`. The loop must therefore filter on message type
   first (the plan already says so in §4.2 (1)).
3. **A genuine `NameOwnerChanged` and the forged one differ on the header, as
   the tray's recogniser assumes.** Genuine: sender `org.freedesktop.DBus`,
   **no destination**. Forged unicast from a peer: sender `:1.1`
   (the bus rewrites the sender), destination `:1.0`. The driver's own
   unicast `NameAcquired` has sender `org.freedesktop.DBus` **and** a
   destination, so the recogniser's destination test (`item.rs:450`) is
   load-bearing, not redundant.
4. **`reply` and `reply_error`.** `blocking::Connection::reply(&Header, &body)`
   and `reply_error(&Header, name, &body)` (`src/blocking/connection/mod.rs:128,141`)
   take a borrowed `Header`. `Header` borrows from the `Message`, so a
   `ReplyHandle` should hold the `Message` (a cheap clone) and call
   `message.header()` when it replies. The spike did that from a **different
   thread** and a **clone** of the connection: `reply_error(&h,
   "org.freedesktop.PolicyKit1.Error.Cancelled", &("dismissed",))` reached the
   caller as `MethodError("org.freedesktop.PolicyKit1.Error.Cancelled", "dismissed")`,
   and `reply(&h, &())` reached it as a `MethodReturn` with the right reply serial.
5. **No object server unless asked for.** `start_object_server` runs from
   `ensure_object_server` (`src/connection/mod.rs:874-889`), called when
   `object_server()` is used or an interface is served. The spike never did,
   and the method call reached the iterator unanswered until the spike
   replied: the macro-free design works. (Read from source; the spike did not
   run an `Introspectable` call. See contradiction 2.)
6. **Backpressure, not loss, on the unfiltered queue.** Capacity is 64
   (`DEFAULT_MAX_QUEUED`); `socket_reader.rs` uses `broadcast_direct(..).await`,
   so a full queue stalls the socket reader and drops nothing, and
   `connection/mod.rs:122-126` documents that the iterator "must be
   continuously iterated". The queue only has an active receiver once the
   iterator exists, so the iterator must be built **before** any traffic that
   matters (the spike created it straight after `build()`).

### Contradictions with the spec and the plan

1. **Dropping every clone does not end the iterator.** The plan's Step 3
   wording ("that closing the connection (dropping every clone) ends the
   iterator") is false. A `MessageStream` holds an `Arc<ConnectionInner>`
   (`src/message_stream.rs`, `struct Inner`), so the iterator keeps the
   connection alive. Measured, `spike close_clones`: the iterator thread was
   still blocked 2 s after every other handle (`agent`, the `DBusProxy`) had
   been dropped. What ends it is `Connection::close()` on any clone
   (`spike close_explicit`: after the buffered messages, one item
   `Err(InputOutput(Custom { kind: BrokenPipe, error: "failed to read from socket" }))`,
   then `is_closed()` is true) or the bus going away (`spike daemon_dies`:
   the same `Err(BrokenPipe)`). Spec §4.2 ("Closing the connection wakes the
   blocking iterator, so the join is bounded") is right if "closing" means
   `close()`; the plan must say so. The shutdown path has to call
   `close()` and treat `Some(Err(..))` as the end, not wait for `None`.
2. **"A worker panic drops the connection" (spec §4.2, F-23, threat R) holds
   only when every clone is gone.** The `ReplyHandle`s the loop holds (queued
   and active requests) and the helper thread hold clones, so a panic in the
   bus thread alone leaves the connection and the unique name alive, and the
   requests whose handles survive are neither answered nor cancelled by
   polkitd until the loop drops them. The bus thread needs a drop guard that
   calls `close()` (or the worker must signal the loop to tear everything
   down). Fail-closed is intact either way; the claim "polkitd cancels the
   sessions itself" is not automatic.
3. **N-13's integration test ("introspection shows only the agent") cannot
   pass as written** if no object server is started: nothing answers
   `org.freedesktop.DBus.Introspectable` or `org.freedesktop.DBus.Peer`, so
   the call gets no reply or a bus-level error. The test should assert that
   no other interface or path is **answered**, or the bus thread should
   answer `Peer.Ping` deliberately. (From source reading; not run.)
4. **Wording in S-9** about `/proc/<pid>` ownership: see U-11 above.
5. **Paths in the plan.** The logind bus selection is
   `celestina/src/energy/logind.rs` (`LogindBus::{System, Address}`, whose
   `builder()` is `Builder::system()` or `Builder::address(..)`, lines 82-98),
   not `providers/energy/logind.rs`. `smoke.sh` pins
   `DBUS_SYSTEM_BUS_ADDRESS=unix:path=$work/no-system-bus` at lines 104 and
   374; the `Address` variant is how tests use a private bus.

## Limits

- Bus policy (U-1) is read from files, not enforced by a broker under test.
- The spike ran on a permissive private bus; it proves how zbus presents
  messages and closes, not what dbus-broker denies.
- U-11 measured procfs behaviour of one kernel (7.2.10) with a Python
  process; it does not cover tools outside the repository that may inspect the
  shell (portals if the shell ever becomes a client, debuggers).
- The `Introspectable`/`Peer` behaviour with no object server is from source.
- Nothing here proves Wayland, compositor, hardware or interaction behaviour.
