## What was wrong

The `celestina` workflow installs `stable` and runs
`cargo clippy --workspace --all-targets --locked -- -D warnings`. The
runner's stable became 1.100.0 on 2026-11-09 and the workflow has been red on
`main` since: run 45311009925 (`a53f6db1`) shows two errors,

```text
error: the loop variable `index` is only used to index `fake.buffers`
  --> crates/celestina-lock/src/view.rs:1067:22
error: this function has a `#[must_use]` attribute with no message, but returns a type already considered as `#[must_use]`
  --> src/providers/keybinds.rs:239:1
```

The sessions of 2026-11-23 and 2026-11-24 checked their units with the
pinned toolchain and with `cargo +1.99 clippy`, the runner's stable of
October, so the five bug units and the cutover landed without seeing them.

The workflow was already red before that, for another reason: run
40063986634 (`3ffac082`, 2026-10-24) failed in
`celestina-lock --test signals` with

```text
panicked at crates/celestina-lock/tests/signals.rs:293:10:
spawn the lock: Os { code: 26, kind: ExecutableFileBusy, message: "Text file busy" }
```

The tests of that binary run on threads; each copies the lock and runs the
copy. A `fork` on one thread inherits the descriptor another thread still
holds open for writing its copy, and until that forked child execs, an exec
of the copy fails with `ETXTBSY`. It is a race of the tests, not of the lock.

and `probe_main` loses the `#[must_use]` its return type already carries.
The three test files spawn the copied lock through `support::spawn_fresh`,
which tries again while the kernel answers "text file busy" (at most 100
times, 10 ms apart) and returns any other error at once.

## Limits

- The workflow's three steps were run here with the runner's toolchain
  version; the runner itself (its image, its load) is only seen in the
  workflow's next run on `main`.
- The busy-executable race was not reproduced here (it needs the runner's
  timing); the retry is reasoned from the error the runner printed.
- The local check of every unit should use the runner's current stable, not a
  version remembered from an earlier month.
