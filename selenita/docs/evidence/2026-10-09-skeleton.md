# Evidence: the skeleton builds and opens the window with its three cards

- **Date:** 2026-10-09
- **Scope:** the Selenita skeleton, delivered inside suite unit `EXT-1-B` of
  [the suite plan](../../../docs/plans/active/2026-10-09-reading-and-capture.md)
  and described in prose in
  [SEL-1's plan](../plans/active/2026-10-09-sel-1-foundation.md): the whole of
  `selenita/` and the app icon
- **Environment:** CachyOS, Rust 1.98.1, cxx-qt 0.9.1, Qt 6.12.0
- **Artifact:** the `selenita` release binary in the shared Cargo target, not
  installed

## Procedure

The full command list with exit codes is in
[the registration evidence](../../../docs/evidence/2026-10-09-selenita-registration.md).
The skeleton's own gates, all exit 0:

```sh
cargo build --release --locked            # in selenita/
sh selenita/scripts/qml-tests.sh
sh selenita/scripts/smoke.sh --binary <release binary>
bash scripts/qmllint-cxxqt.sh selenita
```

## Result

- **Exit:** 0 for every command.
- **Observed:** `tst_main.qml` builds the real `Main.qml` over QML stand-ins
  for the two Rust types (`tests/qml/stubs`): the window constructs with the
  capture, recording and history cards, labelled and stacked in that order,
  starts its activation adapter once, and a `raiseRequested` shows a hidden window
  (5 passed, 0 failed). The smoke starts the binary offscreen for 8 s with
  `SELENITA_FAKE=1`, no QML error, and reads
  `selenita-smoke: cards=3 fake=true textScale=1 fontBody=13`. The Rust tests
  (4) cover the activation adapter (`Activate` raises, `Open` is ignored),
  the appearance values and the `SELENITA_FAKE` switch.
- qmllint reports one warning, in the shared
  `celestina-style/CelestinaIcons.qml` (see the registration evidence);
  Selenita's own QML lints clean.

## Limits

- Nothing captures or records yet. Nothing is installed. The real
  compositor's raise, the keyboard and the look on the session are for the
  author.
