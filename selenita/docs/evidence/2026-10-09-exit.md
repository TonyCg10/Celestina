## Decisions

- The keys live in one `FocusScope` (`KeyMap`) around the cards, the
  window's focus item until a control takes it: a key no control wanted
  bubbles up to the map (so Enter works from a focused switch), a key a
  control took never reaches it (Space on a button, the arrows on a row),
  and a `TextInput` or `TextEdit` holding the focus is checked explicitly,
  so a digit typed there is a character. `Shortcut` items would fire over a
  focused row's own keys. Qt Quick Controls' `AbstractButton` takes only
  Space on its own, so Enter bubbling from a focused button (anything with
  `clicked`, a `Switch` apart) presses that button in the map instead of
  capturing (review, fix round 1); a row opens on Enter only when the row
  itself is the focus item and lets the key pass from its action buttons. The map calls the controller for the target and
  the recording and `host.startCapture()` for Enter, as the activation
  route does; the controller's refusals (busy, no destination) stay its
  own, with their notices.
- Escape returns the focus to the map by dropping the focused control's
  `focus` inside the scope, so no ring stays lit; the suite's Escape closes
  a dialog or a menu, which Selenita does not have.
- A history row is a Tab stop and a list item; its arrows ask the card for
  a neighbour (`walkRequested`, `edgeRequested`) and Delete asks for the
  trash (`trashRequested`) so the card can focus the row at the same index
  once the history is rebuilt (`owedIndex`, settled with `Qt.callLater`
  after `countChanged`). A `Repeater` over the controller's array recreates
  every row on a change, so the focus cannot be kept on an item.
- An `Item` has no `focusReason` in Qt 6.12, so the row notes a pointer
  focus itself (`pointerFocused`, set by its `TapHandler` and cleared when
  the focus leaves) and shows `CelestinaRowHighlight`'s ring only for a
  keyboard focus, as the style's `visualFocus` does.
- The window scrolls a control reached by the keyboard into view
  (`onActiveFocusItemChanged` → `PageScroll.reveal`), which now refuses an
  item outside its column rather than mapping it.
- The inner texts of a row and of a setting row are `Accessible.ignored`,
  so a screen reader hears the row's or the switch's name once; the card's
  eyebrow is ignored too, the grouping being named by the title.
- An owed focus after Delete stands only while the trash is in flight: an
  error notice drops it, a Tab stop focused outside the card drops it (the
  scope a destroyed row hands the focus to is no Tab stop, so the rebuild
  does not), and a second Delete meanwhile is ignored. A focus a pointer
  gave (`pointerFocused`, or a control's `MouseFocusReason`) is not
  scrolled into view.

## Limits

- Screen-reader output was not heard live and no key was pressed on the
  session: the names, roles and keys are checked in `qmltestrunner` only.
  The live steps are in VAL-SEL-SHOT and VAL-SEL-REC.
- Tab into a row's action buttons is not walked by a test beyond the Delete
  from `openAction`.
- A Delete whose entry the real worker trashes later (the stub answers at
  once) focuses the row at the same index only when the history changes
  while the owed focus stands.
- The known issues in STATUS (the portal thread leak, the quit worst case,
  the cancel window between portal calls, the same-tick job dropped after a
  child exit, the history lost-update at quit, the start race) are recorded,
  not fixed: each is bigger than this unit.
- `scripts/complete-production.sh` runs at the landing, not here.
