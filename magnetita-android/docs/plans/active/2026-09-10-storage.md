## Hypothesis

The folder the person picks once in the system's tree picker is the root
the desktop browses: the storage access framework's persisted grant, the
documents contract for listings, entries, ranges and changes, and nothing
the platform does not give. The wire's paths map onto document ids by
appending, so no path is ever built from strings the desktop chose.

## Tangible outcome

The device screen's "Archivos" row; Siderita browsing that folder through
the daemon's mount.

## Scope

- `AND-5-A` — the storage adapter over the document tree (list, stat,
  read, write, mkdir, rename, delete), the grant row, the state sent on
  connect and on grant, the requests as signals; the path arithmetic pure
  and tested.
- `AND-5-B` — the whole phone as the root through the all-files grant,
  since the tree picker refuses the root; the same requests over plain
  files; the tree stays as the narrower choice.

## Exclusions

- The `MediaStore` beyond the shared root.

## Build order

1. `AND-5-A`, then `-B`.

## Implementation exit

The path arithmetic and the signals have JVM tests, `lintRelease` passes,
the release build is on the S25U; the browse itself is `VAL-MAG-15`.
