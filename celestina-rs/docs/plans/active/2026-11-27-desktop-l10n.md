# RS-L10N — Localized values in the desktop entry reader

- **Author-validation checkpoint:** none (the shell's `VAL-CEL-I-015` covers the search)

## Hypothesis

The shell's launcher cannot find an application by the Spanish words its
`.desktop` file carries, because `celestina-core`'s reader drops every
`Key[locale]`. Keeping the localized `Name`, `GenericName`, `Comment` and
`Keywords` values beside the unlocalized ones, bounded, with one tested
accessor that picks a locale by the specification's order, gives the
launcher what it needs without changing any existing field or consumer.

## Tangible outcome

`desktop_entry::DesktopEntry` carries the localized values of those four
keys, `desktop_entry::Locale` parses a locale and reads it from the
environment, and `localized_name`, `localized_generic_name` and
`localized_keywords` return the best value for a locale; Siderita and every
other consumer are unchanged.

rebuilds and verifies every app that links the changed crate.
