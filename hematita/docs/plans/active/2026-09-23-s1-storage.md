# S1 — Storage

- **Opened:** 2026-09-23
- **Plan ID:** s1-storage
- **Status:** active
- **Authorization:** the author asked on 2026-09-23 for a storage analyzer
  inside Hematita, designed in
  [the storage design](../../../../docs/superpowers/specs/2026-09-23-hematita-storage-design.md)
- **Scope:** hematita
- **Implementation checkpoint:** S1
- **Author-validation checkpoint:** `VAL-S1` in [VALIDATION.md](../../../VALIDATION.md)

## Hypothesis

A device-bounded walk with progress can analyse the author's 430 GiB home
while the window stays live, and the list-plus-treemap with verified
duplicates and empty folders lets the author act on what is found without
leaving Hematita.

## Tangible outcome

The installed 1.1.0 has an Almacenamiento section that lists the mount
points with their occupation, browses any of them, scans the folder one is
in with visible progress and cancellation, shows the result as a size list
beside a treemap, finds duplicates (verified by content) and empty folders,
and acts on a selection through Siderita's trash or a confirmed permanent
deletion.

## Scope

- `S1-A` — `hematita-core::usage`: `tree`, `walk`, `empty`, `duplicates`,
  `layout`, `remove`, `mounts`, tested on a real temporary directory; S1
  opened in the documents.
- `S1-A2` — the review's corrections of `S1-A`: symlinked components,
  the empty-folder rule, mount boundaries from `mountinfo`.
- `S1-B` — locations, browsing, `StoragePage`, `PathCrumbs`,
  `LocationList`, `FolderList`, the sixth section, the smoke line.
- `S1-C` — scan worker, analysed mode, `UsageList`, `Treemap`, progress and
  cancel, filters, `DuplicateList` with confirmation, `DetailsCard`.
- `S1-D` — actions: open in Siderita, batch trash through `siderita-ops`,
  guarded permanent deletion, pruning, selection and all-but-one.
- `S1-Z` — implementation exit and 1.1.0.

## Exclusions

- Persisting scan results across runs; scanning across mounts; network
  filesystems' quotas; scheduled scans; any shell integration (the shell is
  in standby); any privilege (a folder the user cannot read is reported,
  never escalated).

## Build order

1. `S1-A`, `S1-A2`, then `S1-B`, `S1-C`, `S1-D`, `S1-Z`.

## Implementation exit

`scripts/complete-production.sh` succeeds; the installed binary lists the
mount points, browses and scans a folder with progress and cancellation,
shows the size list and treemap, finds verified duplicates and empty
folders, and acts on a selection through the trash or a confirmed permanent
deletion.
