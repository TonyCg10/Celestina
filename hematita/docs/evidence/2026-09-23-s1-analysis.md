## What changed

1. **`usage_worker.rs`.** `PROGRESS_INTERVAL = 250 ms`, declared once.
   `spawn_scan(root, generation, qt)` runs `usage::walk::scan` on
   `hematita-scan`; the thread reads `/proc/self/mountinfo` and turns it
   into the boundary set through `usage::mounts::{parse_mountinfo,
   mount_targets}`, rate-limits the progress closure to the interval and
   queues `apply_progress`, then derives the findings (candidates, empty
   folders, unreadable counts) off the Qt thread and queues `apply_tree`.
   `spawn_confirm(Arc<Tree>, groups, generation, qt)` runs
   `duplicates::confirm` group by group on `hematita-confirm`, queueing
   `apply_verified(generation, index, verified)` per group and then
   `confirm_finished`; a group with an unreadable file keeps its unverified
   row. Both return a `WorkerHandle` whose `Drop` cancels its
   `CancellationToken`. The threads are detached by design: joining would
   block the Qt thread until the walk's next cancellation check, and a
   detached thread holds only its own root path or an `Arc<Tree>` snapshot
   and a `CxxQtThread` whose `queue` drops a result once the hub is gone;
   the reason is written in the module doc.
2. **`analysis.rs`.** `mode` gains `scanning` and `analysed`.
   `scanHere()` takes the next generation, drops the previous handles
   (which cancels a running scan and a running check), and spawns;
   `apply_progress` sets `progressFiles`, `progressBytes`, `progressPath`
   under the current generation only. `apply_tree`: on success the tree is
   kept as `Arc<Tree>`, `current` is its root, the lists are written, then
   `mode`, then `revision`, so the result replaces the progress in place;
   `Cancelled` returns to browsing; any other error sets
   `actionOutcome = failed` and returns to browsing. The analysed lists are
   the current node's `children_by_size`, filtered; `treemapRects` is
   `squarify` over all of them in a unit rect, published flat as
   `[id, x, y, w, h]` with the remainder at id `-1`. `enterId(id)` enters a
   folder with children; `up()` goes to the parent inside the tree and, at
   the root, back to browsing the scanned folder; a crumb at or below the
   scanned root moves inside the tree, one above it leaves the analysis.
   `confirmDuplicates()` sets `busy` and checks the groups not yet
   verified; a verified group that splits becomes several rows.
   `toggleSelected`, `clearSelection` and `selectAllButOne` keep a real
   selection (`selectedIds`); the three actions still answer `refused`
   until S1-D. Additions to the contract: `setFilters(duplicates, empty)`
   (the filter buttons' one write) and the refresh of an analysed folder,
   which scans it again.
3. **`analysis_view.rs`.** The pure rules, tested without a QObject:
   `findings` (candidates capped at `SHOWN_GROUPS = 500`, the biggest; the
   page lists and the check reads only those), `marks_below` (a member
   climbs its ancestors until one is already marked, so the cost follows
   the set, not the tree), `marks_exact`, `unreadable_below`, `project`
   (the children a filter keeps: those with a match at or below them),
   `all_but_one` (keeps the lowest id), `group_rows` and `flat_rects`.
4. **QML.** `UsageList` (name, a share bar in the kind colour — folder
   `glyphAccentBlue`, file `glyphAccentViolet`, duplicate
   `glyphAccentCoral`, empty `glyphAccentAmber`, unreadable `textFaint` —
   size, percentage, a check glyph when selected; Space selects, Enter
   enters, Backspace up). `Treemap` (a `Repeater` of `AbstractButton`
   tiles, inset by half `spaceXs`, fill at `accentSoftOpacity`,
   `contentHover` on hover, `surfaceSelected` when selected or current, the
   name only when the tile is wider than three caption heights, the
   remainder in `card` labelled `otros`; tiles the filter does not keep
   fade to `unavailableContentOpacity`; one Tab stop, arrows in reading
   order, `Accessible.Grouping` named `Mapa de <folder>`). `DuplicateList`
   (a header per set, `%1 copias · %2`, the `check` glyph
   `Comprobar contenido`, then `verificado` and `Seleccionar todas menos
   una`; copies indented with their path in `textMuted`). `DetailsCard`
   (name, path, on-disk and apparent size, files below, and the identical copies'
   paths for a verified duplicate). `ScanProgress` (added: the progress block
   both panels show, rather than two copies of it). `StoragePage`: the
   analysed body is a `RowLayout` of the list column (0.42, through
   stretch factors) and the map; the filters are live; the scan button is
   `gauge` (scan here) while browsing and `view-refresh` (scan
   again) once analysed; `info` shows the details card; a
   failed scan says so while browsing. No `Canvas`, no tooltip, no motion.
5. **The S1-B review finding, closed.** `locations.rs::disk_of_source`
   stripped every trailing digit run, so `/dev/dm-0` became `dm-` and a
   bare `/dev/mmcblk0` became `mmcblk`. The rule is now `whole_device`: a
   partition suffix is removed only where the stem still names a device —
   `p<M>` after `nvme…n<N>` or `mmcblk<N>`, the digits after
   `sd`/`vd`/`hd`/`xvd` plus letters — and `dm-<N>`, `md<N>`,
   `loop<N>`, `zram<N>` and a bare `nvme…n<N>` or `mmcblk<N>` stay whole.
   Tested: `dm-0`, `mmcblk0`, `mmcblk0p2`, `md127`, `loop3`, `zram0`,
   `nvme0n1`, `nvme0n1p1`, `nvme0n1p12`, `sda1`, `sdb`, `vda2`.

## Procedure

```sh
cd hematita && cargo fmt --all
hematita/scripts/build-production.sh
cd hematita && cargo test --release --locked --all-targets \
  && cargo clippy --release --all-targets --locked -- -D warnings \
  && cargo fmt --all --check
hematita/scripts/verify-production.sh
QT_QPA_PLATFORM=offscreen QT_ASSUME_STDERR_HAS_CONSOLE=1 \
  HEMATITA_SMOKE_SHAPE=1 HEMATITA_SMOKE_SECTIONS=1 \
  timeout 14 hematita/target/release/hematita
bash scripts/check-architecture-contract.sh
```
