## What changed

1. **`tree.rs`** — `NodeId`, `Kind` (`Dir`, `File`, `Other`), `Node` and
   `Tree`, an arena whose sizes (`allocated`, `apparent`, `files_below`)
   are aggregates of each subtree; `path_of`, `children_by_size`
   (descending allocation, ties by name) and `prune` (unlinks a subtree,
   subtracts it from every ancestor, keeps ids stable, refuses the root).
2. **`walk.rs`** — `scan`: iterative with an explicit stack,
   `symlink_metadata` only, never leaves the root's device (a directory on
   another device is a leaf flagged `other_device`), counts a hard link once
   per scan by `(dev, ino)`, marks an unreadable directory and goes on,
   reports `Progress` every 512 entries and asks the `CancellationToken`
   before every directory and at the same cadence inside one. Errors:
   `Cancelled`, `Root`, `NotADirectory`, and `TooManyEntries` (more entries
   than a `u32` id can address, so the walk stops instead of aliasing).
3. **`empty.rs`** — `empty_folders`: directories with no file at any depth,
   deepest first, never the root, and never a folder below which something
   went unseen (an unreadable directory or another device's mount).
4. **`duplicates.rs`** — `candidates` (files of equal allocation above zero,
   two or more, biggest first) and `confirm` (bucket by a hash of the first
   64 KiB, then of the whole file, then split by byte comparison; the hash
   only narrows, the comparison decides).
5. **`layout.rs`** — `squarify`: the squarified treemap, children below
   0.5 % of the total merged into one remainder tile placed last, equal
   sizes kept in index order, empty for a zero total or a flat rectangle.
6. **`remove.rs`** — `delete_tree`, the suite's only permanent deletion:
   refuses the scanned root, anything outside it (after lexical `.`/`..`
   resolution, so the final link is never followed), a mount root and a
   missing path before touching anything; then lists the whole subtree
   without following links, refusing again if a directory below is another
   device's mount; only then removes, children first, a link as itself,
   asking `cancel` before every entry, and reports entries and allocated
   bytes (a hard link's blocks once).
7. **`mounts.rs`** — `parse_mounts` over `/proc/self/mounts` (octal escapes
   decoded, target bytes kept exact) keeping only file-holding filesystems,
   and `is_shown_location` (`/`, `/home`, under `/mnt`, `/run/media`,
   `/media`).
8. **`Cargo.toml`** gained `celestina-core.workspace = true` for
   `CancellationToken`, justified in the manifest, and both
   `celestina-rs/Cargo.lock` and `hematita/Cargo.lock` record the new edge
   (the second edited to the exact lines cargo writes, because no cargo runs
   under `hematita/` in a crate-only unit); `lib.rs` gained
   `pub mod usage;` and a note that this module is the crate's one
   filesystem-touching domain.
9. The S1 documents opened: the plan, the active plans README, `ROADMAP.md`
   (`active`/`S1`), `STATUS.md`, and `VALIDATION.md` (`VAL-S1`).

## The fixture

`tests/usage_tree.rs` builds, per test, a directory under the system
temporary directory named `hematita-usage-PID-NANOS-COUNTER`:
`big.bin` (4 MiB of `0xAB`), `copy-of-big.bin` (identical),
`same-size.bin` (4 MiB of `0xCD`), `docs/a.txt` and `docs/b.txt` (3 KiB,
identical), `docs/link-to-a.txt` (hard link to `a.txt`), `empty/deeper/`,
`out.lnk` (symbolic link to `/tmp`), `locked/secret.txt` with `locked/`
at mode `000`, and, for the progress test only, 600 one-byte files under
`many/`. Expected sizes are read back with `symlink_metadata`
(`blocks × 512`), never hard-coded. A `Drop` guard restores `locked/` to
`755` and removes the fixture with a test-local recursive removal that
follows no link, so a failing test leaves nothing behind; after every run
below, no `hematita-usage-` directory remained in the temporary directory.
The unreadable-directory assertion is skipped with a note when the tests
run as root (they do not here).

## Limits

- The fixture is on tmpfs; the walk's device boundary is proven only by
  the deletion's mount-root refusal against `/proc` under `/`; no test
  mounts a filesystem inside the fixture, so the walk's `other_device`
  leaf is covered by a hand-built tree in `empty`'s unit test only. On
  btrfs every subvolume has its own device number, so a scan stops at a
  subvolume exactly as at a mount.
- Directories themselves contribute no allocation to the walk's totals, as
  the design says; `du` counts directory blocks, which on ext4 may show as
  a small difference under `VAL-S1`'s 1 % tolerance.
- Nothing here runs in the application yet; the scan worker, the section
  and the actions are `S1-B` to `S1-D`. `verify-production.sh` was not run:
  `S1-A` is crate-only.
