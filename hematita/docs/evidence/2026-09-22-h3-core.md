## What changed

1. **`process.rs`** parses `/proc/PID/stat` (splitting at the *last* `)` so a
   command containing spaces or parentheses does not break the field split),
   `/proc/PID/status` (real uid, `VmRSS`, thread count), `/proc/PID/cmdline`
   (NUL-split, lossy UTF-8, empty for a kernel thread), `/proc/PID/io` (the
   two byte counters that reach the disk), and `/proc/PID/cgroup` into an
   `ApplicationScope` recognising `app-<launcher->id-<n>.scope` and
   `app-id[@instance].service` shapes including the `dbus-:1.3-id@0` case.
   `ProcessSampler` turns successive `(pid, start_ticks, cpu_ticks)` readings
   into a percentage of the whole machine (`elapsed × clock_ticks × cores`),
   keying identity on `(pid, start_ticks)` so a reused pid with a different
   start time is treated as a new process and rated from zero rather than
   inheriting the old one's ticks.
2. **`passwd.rs`** parses `/etc/passwd` into a `uid → login name` map; a
   malformed line is skipped rather than refusing the whole file.
3. **`process_view.rs`** decides, without Qt, which rows survive a
   case-insensitive substring filter over name/pid/application, in what sort
   order (six `SortField`s, either direction, ties broken by pid ascending so
   the order is stable across ticks), and how surviving rows gather into
   `Group`s in first-appearance order, summing CPU and memory of members that
   share an application id. Rows with no application form no group.
4. **Captures** (`tests/fixtures/proc-pid-stat.txt`, `proc-pid-status.txt`,
   `proc-pid-cgroup.txt`, `etc-passwd.txt`) prove the real files have the
   shape the parsers expect, against text taken from this session's own
   shell, which the desktop launched under `app-com.anthropic.Claude-893609.scope`
   (confirmed with `grep -c app- /proc/self/cgroup` printing `1` before the
   capture, per the controller's decision) — the cgroup fixture therefore
   names Claude's own app scope rather than a terminal emulator's, which the
   parser treats identically since it only recognises the shape, not the
   application. The passwd capture is `grep -E '^(root|toni):' /etc/passwd`,
   never the full file.
