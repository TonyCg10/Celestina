## What changed

1. **`actions.rs` (new).** Three workers on threads named
   `hematita-actions`, each queueing one `ActionReport { kind, done, total,
   outcome, removed }` stamped with the scan generation and the action
   epoch. `spawn_open` runs `Command::new("siderita").arg(path).spawn()`
   (a missing binary is `failed`), queues the report, then waits for the
   child so it is reaped. `spawn_trash` calls `siderita_ops::trash` per
   item and stops at `OpError::Cancelled`. `spawn_delete` reads the mount
   boundaries on its own thread and calls `delete_tree(path, within,
   boundaries, cancel)` with `within` the scanned root; a `Refused` result
   counts as not done. `removed` lists only the ids that succeeded, with
   the allocated bytes of the tree snapshot. Trash and deletion return a
   `WorkerHandle` whose drop cancels them.
2. **Outcome mapping.** `outcome_of(done, total, refused_all)`: every item
   refused is `refused`; all done is `done`; some done is `partial`; none
   done is `failed`. A refusal of some items among IO failures is
   `failed`, among successes `partial`.
3. **`analysis.rs`.** `openSelected`, `trashSelected`, `deleteSelected`
   act on the outermost selected entries (an entry below another selected
   one is dropped, and the scanned root is never selectable), one action
   at a time, with `busy` set while it runs. `apply_action` writes
   `actionKind`, `actionDone`, `actionTotal`, `actionBytes` (added: the
   bytes the outcome line names) and `actionOutcome`, then prunes exactly
   the reported ids with `Tree::prune` (`Arc::make_mut`), drops them and
   everything below them from the candidates, the verified sets, the
   unreadable flags, the empty folders and the selection, subtracts their
   unreadable counts from the ancestors, returns to the root if the
   analysed folder went, and republishes. `selectedBytes` (added) is the
   allocation the selection would free, for the confirmation question.
4. **The four carried S1-C findings.**
   1. A cancelled check could kill a restarted one: the hub now keeps a
      `confirm_epoch` moved by every start, cancel and pruning;
      `spawn_confirm` carries it, and `apply_verified`,
      `apply_unreadable` and `confirm_finished` drop any result under
      another epoch.
   2. A check of the old tree could land on a pruned one: pruning cancels
      the running check and moves the epoch.
   3. The 500-group cap is now stated: `Findings.hidden_groups` counts the
      groups beyond `SHOWN_GROUPS`; the hub publishes `hiddenGroupCount`
      and `DuplicateList` shows the count at its foot.
   4. A group with an unreadable copy now says so: the confirm worker
      queues `apply_unreadable`; `groupUnreadable` (0/1) per row;
      `DuplicateList` shows the reason on it, and "all but one" is refused
      for it in the hub and not offered in the list.
   Minor: coral paints only copies of verified sets; an unverified
   candidate keeps the plain file colour and shows its group count
   (`entryCopies`, added) beside its percentage.
5. **QML.** The actions capsule is enabled by a selection while nothing is
   busy. Delete in the list, the duplicate list or the map asks to trash.
   Trash of one entry goes at once, of more through `ConfirmDialog`
   (count and size in the question); deletion always asks, the button
   says Borrar. The outcome line composes the verb and the typed outcome.
   `info` keeps showing `DetailsCard`. No new QML file.
6. **`Cargo.toml`.** `siderita-ops` as a path dependency, with its reason;
   `Cargo.lock` gained the one package.
