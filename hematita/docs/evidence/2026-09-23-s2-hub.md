## What changed

1. **The split.** `analysis.rs` went from 1533 to 779 lines. It keeps the
   bridge, the locations and browsing state, navigation and the
   publication. `analysis_session.rs` (new) holds `Session`, a plain struct
   with the tree, findings, verdicts, selection, analysed folder, marks,
   worker handles and the confirm and action epochs, and every rule about
   ids (`mark_duplicates`, `stop_confirm`, `confirm_current`,
   `action_items`, `selected_totals`, `prune`, `graft`, `chain`, `node_id`,
   the analysed view), with unit tests. `analysis_workers.rs` (new, a child
   module of the bridge file) starts the scan, content check, actions and
   graft scans and applies their answers, each delegating to the session.
   `analysis_view.rs` keeps its API; its test tree gained the
   `hard_link_names` field `S2-A` added to `Tree`.
2. **Partial removals.** `actions.rs` passes the item's recorded device and
   inode to `delete_tree` as `expected`. A `Failure` whose `removed.entries`
   is above zero is `Step::Partial`: the report lists the item in
   `partial` and adds the bytes removed to `partial_bytes`, and the outcome
   is `partial`. A `Failure` with nothing removed is still `refused`,
   `cancelled` or `failed`.
3. **The graft flow.** For each partial id the hub checks the id is live,
   takes its path from the tree and calls `usage_worker::spawn_graft`,
   which reads the mount table and runs `walk::scan_subtree` and
   `analysis_view::findings` on a `hematita-graft` thread. The handle is
   kept in `Session::grafts`; `busy` is on and no action may start while
   one runs; a rescan, browsing away or leaving drops the handles, which
   cancels them, and moves the generation, which drops a late answer.
   `apply_graft` checks the generation and that the id is still awaited,
   then calls `Session::graft` (the stale subtree's ids leave the findings,
   verdicts and selection, the fresh empty folders and unreadable counts
   join under their new ids, the analysed folder follows the graft), or
   prunes the id when the folder is gone (`NotFound` or not a directory),
   and republishes. The graft thread reads the mount table itself instead
   of taking it from the hub, so the Qt thread reads nothing.
4. **The `Weak` confirm worker.** `spawn_confirm` takes a `Weak<Tree>` and
   upgrades it once per group, dropping the strong reference after each
   comparison. A pruning or graft on the Qt thread therefore finds the
   hub's `Arc` unshared and `Arc::make_mut` changes it in place. Residual:
   a group being compared at that moment still holds its strong
   reference, so that one change copies the tree once; the epoch moved by
   `stop_confirm` still drops the verdict. When the upgrade fails the
   worker stops.
5. **Live ids.** `Session::node_id` answers only for `Tree::is_live` ids,
   so an id of a pruned or replaced subtree is refused by `enterId` and
   `toggleSelected`.
6. **Bound confirmation.** `requestTrash` and `requestDelete` put
   `count: selectedCount` in the dialog's payload; `trashSelected(expected)`
   and `deleteSelected(expected)` set `actionOutcome` to `refused` without
   acting when the outermost selection no longer holds `expected` entries.
7. **VAL-S2.** The `chmod 000` step now expects the whole deletion refused
   with nothing removed (the read-only pass cannot check that folder for a
   mount); a new `chmod 555` step expects the partial count and the true
   remaining size after the graft. This closes the S2-A2 re-review note.

## Procedure

```sh
cd hematita && cargo fmt --all
hematita/scripts/build-production.sh
cd hematita && cargo test --release --locked --all-targets \
  && cargo clippy --release --all-targets --locked -- -D warnings \
  && cargo fmt --all --check
hematita/scripts/verify-production.sh
QT_QPA_PLATFORM=offscreen QT_ASSUME_STDERR_HAS_CONSOLE=1 \
  HEMATITA_SMOKE_SHAPE=1 HEMATITA_SMOKE_SECTIONS=1 \
  timeout 14 hematita/target/release/hematita
bash scripts/check-architecture-contract.sh
```

  inside it only, as `S2-A` recorded.
